# KB Previl — 서울 요식업 입점 위치 추천

서울에서 음식점을 열 자리를 찾을 때, **어디가 얼마나 오래 버티는 자리인지**를
100m 칸 단위로 등급을 매겨 보여줍니다.

등급은 느낌이 아니라 과거 기록으로 확인한 숫자입니다.
**1등급 자리에 문을 연 가게의 3년 생존율은 80.1%, 9등급 자리는 10.1%**였습니다.

---

## 1. 실행하기

### 준비물

**파이썬 3.10 이상**이 설치된 컴퓨터. 그게 전부입니다.
(터미널에 `python --version` 을 쳐서 확인할 수 있습니다. 검증한 환경은 3.10.11 입니다.)

라이브러리는 직접 설치하지 않아도 됩니다 — `run.py` 가 전용 가상환경(`.venv`)을
만들고 필요한 것만 알아서 받습니다. 시스템 파이썬은 건드리지 않습니다.
무엇이 설치되는지는 아래 **「6. 요구 사항」** 에 적어 뒀습니다.

### 순서

**①** 받은 zip 을 풉니다. **`previl` 폴더 하나**가 생깁니다.

- zip 이 **하나**(`KB_Previl_all.zip`)라면 그것만 풀면 끝입니다.
- zip 이 **둘**이라면 `KB_Previl_service.zip` 을 먼저 풀고,
  `KB_Previl_db.zip` 은 그렇게 생긴 **`previl` 폴더 안에** 풉니다.

**②** `.env` 를 압축 없이 그대로 **`previl` 안에** 넣습니다.

다 하고 나면 이런 모양이 됩니다.

```
previl/
  ├─ run.bat           ← 실행 파일 (더블클릭)
  ├─ run.py            ← 실제 실행 로직 (터미널용)
  ├─ README.md         ← 이 문서
  ├─ kb-demo.db        ← 데이터 (DB zip 에서 나온 것)
  ├─ .env              ← API 키
  ├─ verify.ipynb
  ├─ requirements.txt  requirements-full.txt
  ├─ web/              ← 화면 (빌드 완료본)
  └─ service/  model/  pipeline/  frontend/
```

> **`run.bat` 와 `kb-demo.db` 와 `.env` 가 나란히 같은 층**에 있으면 됩니다.

**③** **`run.bat` 을 더블클릭**합니다. (Windows)

터미널이 편하시면 `previl` 폴더에서 한 줄을 쳐도 같습니다 — macOS·리눅스는
이쪽입니다.

```bash
cd previl
python run.py
```

**④** 끝입니다. 처음 한 번은 준비하느라 1~2분 걸리고, 준비가 끝나면 브라우저가
저절로 열립니다. 열리지 않으면 주소창에 **http://127.0.0.1:8000** 을 직접 칩니다.

### 실행하면 이런 게 순서대로 보입니다

```
[1/4] 가상환경 생성 — .venv
[2/4] 의존성 설치 — 처음이면 1~2분 걸린다
[3/4] 데이터베이스 — kb-demo.db (255 MB)
[4/4] 서버 기동 — http://127.0.0.1:8000  (멈추려면 Ctrl+C)
```

멈추려면 터미널에서 **Ctrl+C** 를 누릅니다.
다시 켤 때는 `run.bat` 을 다시 더블클릭(터미널이면 `python run.py`)하면 되고,
두 번째부터는 몇 초면 뜹니다.

### 잘 안 될 때

| 증상 | 해결 |
|---|---|
| `python` 을 못 찾는다고 나옴 | `python3 run.py` 로 쳐 봅니다 |
| 8000번 포트가 이미 쓰인다고 나옴 | `python run.py --port 9000` |
| 브라우저가 안 열림 | 주소창에 `http://127.0.0.1:8000` 직접 입력 |
| 지도만 회색으로 나옴 | 인터넷 연결을 확인합니다 (지도 배경은 외부에서 받아옵니다) |
| 칸을 눌러도 건물 윤곽이 안 나옴 | `.env` 가 `run.py` 옆에 있는지, 인터넷이 되는지 확인합니다. 건물 모양만 외부에서 받아오므로, 안 나와도 등급·추천·손익은 전부 정상입니다 |
| DB 를 못 찾는다고 나옴 | `kb-demo.db` 가 `run.py` 와 같은 폴더에 있는지 확인합니다 |

## 2. 무엇을 하는 프로그램인가

화면은 다섯 단계로 흐릅니다.

**업종과 지역을 고르면 → 그 조건에서 좋은 자리를 지도 위에 등급으로 칠해 주고 →
자리 하나를 누르면 그 자리에 대해 아는 것을 전부 펼쳐 보이고 → 두 자리를 나란히
비교**할 수 있습니다.

### 등급은 어떻게 나오나요

서울에서 지난 20년간 문을 연 음식점 **53만 곳의 개업·폐업 기록**을 모았습니다.
그리고 이렇게 물었습니다 — *"어떤 자리에서 문을 연 가게가 더 오래 버텼는가?"*

주변에 가게가 몇 개나 있었는지, 같은 업종이 얼마나 몰려 있었는지, 최근 몇 년간
그 동네에서 개업과 폐업이 얼마나 일어났는지, 지하철에서 얼마나 가까운지 —
**자리 자체의 성격만** 골라서 학습했습니다. 가게 크기나 층수처럼 *주인의 형편*에
해당하는 것은 일부러 뺐습니다. 그걸 넣으면 「좋은 자리」가 아니라 「돈 많은 사람」을
맞히는 모델이 되기 때문입니다.

중요한 건 **채점을 미래로 하지 않았다는 점**입니다. 2022년까지의 기록만 보고 배운
다음, **한 번도 보지 못한 2023년 개업 가게들**이 실제로 어떻게 됐는지로 채점했습니다.
그 결과가 위의 80.1% 대 10.1% 입니다.

### 그 밖에 보여 주는 것

| 화면의 카드 | 무엇을 말하나 |
|---|---|
| 입지 등급 | 1~9등급. 그 등급 자리들이 **실제로 3년을 버틴 비율**이 함께 붙습니다 |
| 얼마나 벌어야 하나 | 임대료·인건비를 감당하려면 필요한 매출 |
| 권리금 | 비슷한 조건의 자리들이 실제로 주고받은 금액대 |
| 이 동네는 어떻게 변하고 있나 | 최근 개업·폐업 흐름 |
| 주변엔 어떤 가게가 있나 | 걸어갈 거리 안 영업 중인 가게 구성 |
| 칸 안의 건물 | 고른 칸을 누르면 그 안의 건물이 지도에 파란 윤곽으로 뜹니다. **모양을 보여줄 뿐 등급·순위와 무관합니다** |
| 여긴 누구와 오는 자리인가 | 손님 후기에서 센 동반자 구성 |
| AI 요약 | 검증된 근거 중 무엇을 강조할지 골라 정리 |

**숫자와 문장은 프로그램이 검증된 틀로 만듭니다.** AI 는 실제 데이터가 있는 근거
문장 가운데 2~4개를 고를 뿐, 문장을 새로 쓰거나 숫자를 만들 수 없습니다. 그래서
화면의 숫자와 문장 속 숫자가 어긋날 수 없습니다.

## 3. 솔직하게 말해 둘 것

1. **1등급 자리에서도 5곳 중 1곳은 3년 안에 문을 닫습니다.** 반대로 9등급에서도
   10곳 중 1곳은 살아남습니다. 등급은 확률이지 보장이 아닙니다.
2. **이 모델은 「무작위보다 확실히 나은」 수준입니다.** 「잘 맞힌다」고 말하지
   않겠습니다. 그 자리의 과거 성적만 보는 것보다 나은 정도입니다.
3. **예측은 100m 칸까지입니다.** 같은 칸 안의 어느 건물, 몇 층인지까지는 예측하지
   않습니다. 건물 정보는 사실만 보여 줍니다.
4. **매출 자료는 상권 단위**라서, 같은 상권에 있는 칸들은 매출 항목에서 같은 값이
   나옵니다.
5. **서울 격자의 약 절반은 상권 밖**이라 매출 기반 항목(부담률·권리금)이 나오지
   않습니다. 없는 것은 지어내지 않고 비워 둡니다.
6. **「누구와 오는 자리인가」는 예측이 아니라 후기에서 센 관측**이고 상권 단위입니다.
   등급이나 추천 순서에는 쓰지 않았습니다.

## 4. 더 해 볼 수 있는 것

### 제대로 도는지 직접 확인하기

`verify.ipynb` 를 주피터나 VS Code 로 열어 위에서부터 실행하면 됩니다.
터미널에서 한 번에 돌리려면 아래 명령을 사용합니다.

Windows PowerShell:

```powershell
.venv\Scripts\python -m pip install -r requirements-full.txt   # 처음 한 번
.venv\Scripts\python -m nbconvert --to notebook --execute verify.ipynb --stdout
```

macOS / Linux:

```bash
.venv/bin/python -m pip install -r requirements-full.txt   # 처음 한 번
.venv/bin/python -m nbconvert --to notebook --execute verify.ipynb --stdout
```

데이터가 다 들어와 있는지, 등급이 실제로 생존율 순인지, API 와 화면이 응답하는지를
차례로 확인하고 그래프로도 보여 줍니다. 어긋나는 게 있으면 그 자리에서 멈춥니다.

### API 직접 보기

서버를 띄운 상태에서 **http://127.0.0.1:8000/docs** 로 들어가면 모든 API 를
브라우저에서 바로 눌러 볼 수 있습니다.

### 데이터를 처음부터 다시 만들기

`kb-demo.db` 없이 `.env` 만 두고 실행하면, 프로그램이 원천 데이터를 직접 받아
데이터베이스를 처음부터 만듭니다.

```bash
python run.py --backfill-only --dry-run   # 무엇을 할지 먼저 보기
python run.py --backfill                  # 실제로 만들기
```

다만 서울 열린데이터가 하루 900번만 부를 수 있어서 **하루 이상 걸립니다.**
중간에 끊기면 같은 명령을 다시 치면 이어서 받습니다. 평소에는 동봉된 DB 를 쓰는
쪽이 맞습니다.

### 실행 옵션

| 옵션 | 뜻 |
|---|---|
| `--port 9000` | 다른 포트로 띄웁니다 |
| `--no-browser` | 브라우저를 자동으로 열지 않습니다 |
| `--backfill` | 데이터를 원천에서 다시 만듭니다 |
| `--backfill-only --dry-run` | 점검과 계획만 보여 줍니다 |
