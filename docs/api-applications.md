승인 소요는 대체로 즉시~2영업일이며, data.go.kr 오픈API는 **승인 전 호출 시 `500 Unexpected errors`** 가 납니다(엔드포인트 오류와 구분이 안 되니 승인 후 재확인 필요).

## 0순위 — 신청 불필요, 호출도 불필요 (캐시에 이미 있다)

### 휴게음식점 인허가 — 카페가 통째로 안 보이는 원인

`licence` 테이블은 **일반음식점만** 담는다. 카페는 대부분 **휴게음식점**으로
인허가되므로 우리 눈에 안 들어온다. 실측:

| 원천 | 서울 카페 «영업 중» | 이력 |
|---|---|---|
| `licence` 까페 (일반음식점) | **1,239** | 있음 |
| `licence_rest` 커피숍 (휴게음식점) | **14,731** (전체 40,279) | **있음** |
| `store` SEMAS 카페 | 21,619 | 없음 (현재 스냅샷) |

**신청할 것도 부를 것도 없다.** `pipeline/cache/licence_rest.jsonl`(152MB,
146,507건)이 이미 있고, 2026-07-29 콜드 재구축 때 `licence_rest` 테이블만
안 채운 것이다. 복구는 API 호출 0회:

```bash
python -m model.tier2 --cache licence_rest      # 캐시에서 licence_rest 적재
```

캐시 내역: 커피숍 40,279 · 기타 휴게음식점 27,113 · 일반조리판매 22,033 ·
다방 17,718 · 편의점 13,182 · 과자점 8,626 · 패스트푸드 8,354.

**주의 — 이 데이터를 «모델»에 넣는 것은 이미 기각됐다**(§8-C, 번들 홀드아웃
ΔAUC +0.0006, CI 가 0 포함). 여기서 말하는 것은 **표시·커버리지**다. 예측에
도움이 안 되는 것과, 카페 창업자에게 보여줄 경쟁 수가 실제의 8% 인 것은
다른 문제다.

SEMAS(`store`)는 2026-07-29 에 표시용으로 붙였지만 **이력이 없어** 개·폐업
누계와 지역 생존율을 만들 수 없다. `licence_rest` 는 그것이 되므로, 카페
문제의 최종 답은 이쪽이다.

## 1순위 — 창업비용 축을 만들려면 필수

### 공정거래위원회 가맹사업 정보공개서 (5종)

프랜차이즈 브랜드별 **실제 창업비용**이 공시되는 유일한 소스. 개인 창업의 인테리어·설비비를 추정하는 벤치마크로도 쓸 예정.

| 데이터셋 | 번호 | 얻는 것 |
|---|---|---|
| 브랜드별 창업 금액 현황 | `15110265` | 가맹금·보증금·교육비·기타 (브랜드 단위) |
| 업종별 창업비용 현황 | `15110293` | 업종 평균 창업비용 |
| 정보공개서 목록 조회 | `15125569` | 등록 정보공개서 목록 |
| 정보공개서 목차 조회 | `15125570` | 문서 목차 |
| 정보공개서 본문 조회 | `15125571` | 본문 (인테리어 단가 등 상세) |

신청: https://www.data.go.kr → 데이터셋 번호로 검색 → **활용신청** → 활용목적 "학술연구/공모전"
※ 5개 각각 신청해야 합니다. 한 번에 안 됩니다.

**현재 상태 (2026-07-26 실호출)**: 전부 `500 Unexpected errors`. data.go.kr은 **미승인**과 **엔드포인트 오류**를 같은 500으로 돌려주므로 둘을 구분할 수 없습니다. 확인해 주실 것:

1. **마이페이지 → 오픈API → 활용신청 현황**에서 승인 상태 (승인 대기/승인 완료)
2. 승인 완료라면 해당 API **상세기능** 화면의 **요청주소(엔드포인트 URL)** 전문

요청주소만 주시면 즉시 붙입니다. 제가 추정한 경로들(`FftcBrandOpbizCost2_Service` 등)은 전부 실패했습니다.

## 2순위 — 비용 축 보강

### 한국부동산원 — R-ONE 자체 인증키 ★ 실호출로 경로 확인됨

**신청: https://www.reb.or.kr/r-one → 오픈API → 인증키 신청** (data.go.kr 키와 **별개**입니다)

```
GET https://www.reb.or.kr/r-one/openapi/SttsApiTblData.do?KEY=<R-ONE키>&Type=json&...
→ 현재 응답: ERROR-290 "인증키가 유효하지 않습니다"  (= 경로는 정확, 키만 없음)
```

data.go.kr 쪽 오픈API(`15002275`)는 계속 `500`이라 엔드포인트조차 확인이 안 되는데, **R-ONE 자체 API는 경로가 확인됐습니다.** 이쪽이 확실합니다.

**주의: 해상도가 매우 거칩니다.** 부동산원 상권은 전국 368개(서울 100개 안팎)로, 우리 격자 23,572개 기준 값 하나가 격자 200개 이상을 덮습니다. **특정 매물의 임대료로는 못 씁니다.**

그래서 파이프라인은 임대료를 **사용자 입력**으로 받도록 이미 구현했습니다(`model/economics.py`). R-ONE 키가 들어오면 추가되는 건 **"이 매물이 그 동네 시세 대비 비싼가/싼가"** 비교입니다 — 시세 비교는 권역 해상도로도 유효한 질문이라 그대로 쓸 수 있습니다.

| 데이터셋 | 번호 | 형태 |
|---|---|---|
| 소규모상가 임대료 | `15069766` | 파일(CSV) |
| 소규모상가 공실률 | `15069726` | 파일(CSV) |
| 집합상가 임대료 | `15069791` | 파일(CSV) |
| 전국 상권 구획도 | `15086933` | 파일(폴리곤) — 임대료를 격자에 붙이려면 필요 |
| 임대동향 통계 조회 서비스 | `15002275` | 오픈API |

**파일데이터(CSV)는 활용신청 없이 바로 다운로드됩니다.** 오픈API(`15002275`)만 신청 대상이고, 급하지 않으면 CSV로 충분합니다.

### VWORLD 데이터API

키(`VWORLD_API_KEY`)는 이미 있고 **지오코딩은 작동**하는데, 데이터API는 권한이 없어 `"인증키 정보가 올바르지 않습니다"`가 납니다. 키 문제가 아니라 **API별 활용신청 문제**입니다.

신청: https://www.vworld.kr → 오픈API → 인증키 관리 → 기존 키에 아래 API 추가

| 레이어 | 코드 | 얻는 것 |
|---|---|---|
| 연속지적도 | `LP_PA_CBND_BUBUN` | 필지 경계·면적 |
| 용도지역 | `LT_C_UQ111` | 상업/주거/공업 — 업종 제한 확인 |
| 건물 | `LT_C_SPBD` | 건물 층수·용도 |

용도: 격자 안에서 "실제로 음식점을 열 수 있는 자리인지"를 거르는 물리적 필터.

## 3순위 — 수요 정밀화

### SGIS 통계지리정보 (통계청) — ✅ 키 발급 완료 (2026-07-29 확인)

`SGIS_CONSUMER_KEY` / `SGIS_CONSUMER_SECRET` 둘 다 `.env`에 있고 실제로 쓰이고
있습니다 — `grid_sgis` 23,552행 · `sgis_dong` 426행 · `sgis_jipgyegu` 19,097행.
`corp_cnt`·`tot_worker` 등 배후 피처의 결측이 0.8% 뿐인 것이 그 결과입니다.

**남은 제약은 키가 아니라 경계입니다.** 집계구 «통계»는 받아지는데 집계구
«경계 폴리곤»이 오픈API 로 제공되지 않습니다. 그래서 집계구 값을 격자에 붙일
공간 근거가 없고, 수요 피처는 여전히 **행정동(서울 424개)** 해상도에 묶여
있습니다. 같은 동 안의 격자는 이 축에서 전부 동점입니다.

이것을 풀려면 경계를 다른 데서 얻어야 합니다:

| 경로 | 얻는 것 | 상태 |
|---|---|---|
| SGIS 오픈API | 집계구 경계 | **미제공** |
| 통계청 «통계지리정보서비스» 자료제공 신청 (SHP) | 집계구 경계 SHP | 별도 신청 — 기관/연구 목적 심사 |
| VWORLD 연속지적도 `LP_PA_CBND_BUBUN` | 필지 경계 (집계구는 아님) | 아래 VWORLD 항목 참조 |

※ 거친 값을 격자로 «배분»하는 것은 이 프로젝트의 금지 항목입니다(CLAUDE.md
비협상 3). 경계가 없으면 해상도를 올릴 방법도 없다는 뜻입니다.

## 신청 후 확인 방법

키를 받으면 `.env`에 추가하고 알려주세요. 아래로 즉시 검증합니다.

```
python probe/p9_newapis.py        # 신규 승인분 일괄 실호출 (신청 완료 후 작성)
```

공정위·부동산원은 기존 `DATA_GO_KR_SERVICE_KEY`가 그대로 쓰이므로 **키 추가 없이 승인만 되면 됩니다.**
R-ONE 만 별도 키(`R_ONE_API_KEY`)가 필요합니다.

## 정리 — 무엇이 막혀 있고 무엇이 안 막혀 있나

| 항목 | 막은 것 | 필요한 행동 |
|---|---|---|
| 휴게음식점(카페) | **아무것도** | `python -m model.tier2 --cache licence_rest` |
| 공정위 창업비용 | 승인 상태 불명 | data.go.kr 마이페이지에서 승인 확인 + 요청주소 전달 |
| R-ONE 임대료 | 자체 키 없음 | reb.or.kr/r-one 에서 인증키 신청 (CSV 는 신청 없이 즉시) |
| 집계구 해상도 | **경계 미제공** | 통계청 SHP 자료제공 신청 (키로는 안 됨) |
| VWORLD 물리입지 | API별 활용신청 | vworld.kr 기존 키에 3개 API 추가 |
