## 1. 한 장 요약

> 서울에서 음식점을 열 자리를, **100m 격자 단위로 등급을 매겨** 추천한다.
> 그 등급은 의견이 아니라 **과거 데이터로 검증된 것**이다 —
> 1등급 자리의 실측 3년 생존율은 **80.1%**, 9등급은
> **10.1%**(n=317, 95% CI 7.2–13.9%)다.

세 문장으로 늘리면:

1. 서울 일반음식점 인허가 **53만 5,715건**(1900~2026, 개업·폐업 전 이력. 밀도가 생기는 것은 1980년대부터다)을 100m 격자에 올렸다.
2. 개업 시점의 상권 상태를 인허가 이력만으로 복원해(as-of), **2005~2022년으로 학습하고 2023년으로 검증**했다.
3. 그 등급 위에 **생존확률을 반영한 손익**과 **권리금 적정가**를 계산한다.

**차별점 한 줄**: 대부분의 상권분석 서비스는 "지금 이 동네가 어떤가"를 보여준다. 우리는 **"여기 연 사람들이 실제로 얼마나 버텼는가"**를 검증해서 등급을 매긴다.

## 2. 무엇을 계산하는가 — 3층 구조

```
[1층] 입지 등급        이 자리는 몇 등급인가          ← 검증된 예측 (홀드아웃)
        ↓
[2층] 생존 반영 손익    3년 뒤 얼마가 남는가            ← 등급별 실측 생존곡선 × 비용
        ↓
[3층] 권리금 적정가     이 권리금이 합당한가            ← 초과수익 환원 + 원가법
```

각 층이 아래층의 출력을 입력으로 쓴다. **모델은 1층에만 있고, 2·3층은 결정론적 산식**이다. 심사에서 "왜 이 숫자인가"를 물었을 때 2·3층은 계산기를 열어 보여줄 수 있어야 한다.

### 3.2 좌표계 — 발표에서 쓸 만한 에피소드

인허가는 **EPSG:5174**, 서울 상권은 **EPSG:5181**로 **서로 다르다**. 후보 좌표계들이 원점을 공유하고 datum만 달라서, 틀린 걸 골라도 점이 서울 안에 그럴듯하게 떨어진다.

> 실제로 처음 EPSG:2097로 가정했고, **내부 검증 14/14가 전부 통과하는 상태에서 모든 점포가 1~2격자씩 밀려 있었다.** 역지오코딩으로 각 레코드의 주소와 대조해서야 잡혔다.

**슬라이드 메시지**: "검증이 통과했다고 맞는 게 아니다. 외부 관측으로 대조해야 한다." — 방법론 축의 좋은 재료다.

### 3.3 데이터 함정 3개

1. **`APVPERMYMD`(인허가일자)는 뒤에 공백이 붙은 24자 문자열**이다. `YYYYMMDD` 8자로 가정하면 전량 파싱 실패한다.
2. **매출이 없는 격자는 NULL이지 0이 아니다.** 상권 밖 격자가 **49.5%**다. 0을 넣으면 그 자리가 "최악의 입지"로 랭크돼 추천이 조용히 거짓이 된다.
3. **거친 데이터를 격자에 배분하지 않는다.** 행정동 인구를 격자에 나눠 담으면 산과 하천에도 인구가 배정된다. 거친 값은 "이 격자가 속한 단위의 값"으로 붙이고, **격자 간 순위는 점 단위 피처만 결정한다.**

## 4. 파이프라인 — 18단계

```
schema → collect → normalize → tier2 → cohort → grid → geocode → sgis
  → sgis_match → features → access → addr_history → concept → concept_mix
  → precompute → ui_curves → succession → party
```

`tier2`(휴게음식점)는 `concept_mix` 보다 앞이어야 한다. 카페·베이커리는 일반음식점이 아니라 휴게음식점으로 인허가되고 `concept_mix` 가 그 표를 읽는다.

| 산출 테이블 | 행수 | 내용 |
|---|---:|---|
| `licence` | 535,715 | 인허가 원천 (정규화·격자 배정 완료) |
| `grid` / `grid_feature` | 23,573 | 100m 격자(EPSG:5179) + 피처 |
| `addr_tenancy` | 535,487 | **자리 이력** — 주소×업종별 임차 연쇄 |
| `grid_score` | **241,776** | 사전계산 등급 = **12업태 × 20,148격자** |
| `succession_score` | **241,776** | M2 승계확률 서빙 테이블 |
| `shop_concept` | 477,490 | 상호명 기반 콘셉트 태깅 |

**12업태**: 한식 · 중국식 · 일식 · 경양식 · 분식 · 까페 · 통닭(치킨) · 호프/통닭 · 정종/대포집/소주방 · 식육(숯불구이) · 기타 · 외국음식전문점(인도,태국등)

> 격자 23,573개 중 **20,148개만 채점**한다. 이웃 이력 20건 미만인 격자는 **의도적으로 뺀다** — 이력이 없는 칸이 "실패 기록이 없어서" 좋게 랭크되는 것이 이 도구가 할 수 있는 가장 나쁜 거짓말이기 때문이다. 빠진 격자는 "평가 불가"로 응답한다.

끝점이 2022인 이유는 랜딩 그래프와 같다 — 2023 개업분은 3년이 지난 것이 14,992건 중 8,762건뿐인 반쪽 코호트라 `/api/meta`가 계열에서 뺀다. 반쪽으로 재면 58.8%지만 앞 연도들과 같은 조건이 아니다.
(14,992·8,762는 **인허가 전수 계열**의 수이고, §5.1 표의 판정 표본 13,456·7,915는
**모델 검증 코호트** — 좌표·업태 필터를 거친 학습셋 기준 — 라 모집단이 다르다.
두 수를 이어 붙이거나 빼서 읽지 말 것.)

### 5.1-B 예측 성능 스펙트럼 — 과제에 따라 AUC 0.64~0.84

0.6383은 **가장 어려운 과제**(3년 · 순수 입지)의 값이다. 같은 시스템을 실제
사용 장면의 질문 — 「이 자리·이 조건이면 **계약기간(1~2년)** 을 버티는가」 —
으로 재면 판별력이 크게 오른다. 전부 시간 분리 + 동일 누수 가드 + 사전 등록
판정(단조·CI) 통과, 재현은 `python -m model.recency --features NUM2`.

| 과제 (기간 · 정보) | 홀드아웃 | AUC | 베이스라인 | 십분위 격차 |
|---|---|---|---|---|
| **1년 · 자리+점포조건** | 2025 (n=6,670) | **0.8375** | 0.5447 | **93.4%p** (96.1% vs 2.7%) |
| **1년 · 자리+점포조건** | 2024 (n=13,287) | **0.8128** | 0.4951 | 80.3%p (95.8% vs 15.5%) |
| 1년 · 순수 입지 | 2024 (n=13,284) | 0.7273 | 0.4951 | 64.4%p |
| 2년 · 자리+점포조건 | 2024 (n=7,935) | 0.7206 | 0.5381 | 69.6%p |
| 2년 · 자리+점포조건 | 2023 (n=13,456) | 0.7100 | 0.5481 | 66.4%p |
| 3년 · 자리+점포조건 | 2023 (n=7,915) | 0.6789 | 0.5668 | 59.1%p |

주의 — **2025 홀드아웃과 3년 셀은 상반기 개업분만 판정 가능한 검열 셀**이다
(코호트 전량 셀은 2024의 1·2년). 1년 베이스라인(0.4951 등)은 0.5 아래로
퇴화하는 해가 있어, 절대 AUC가 커질수록 "베이스라인 대비"라는 주장의
실질은 오히려 약해진다 — 마진과 함께 읽을 것.

**분류 지표** (1년 모델 · 2025 홀드아웃 · 임계값은 train에서만 결정 —
재현 `python -m model.clf_metrics`):

| 지표 | 모델 | 전원-생존 베이스라인 |
|---|---|---|
| Accuracy | **0.886** | 0.786 |
| 생존 F1 | **0.932** (P 0.880 · R 0.990) | 0.880 |
| **폐업 Precision** | **0.948** (Recall 0.490, t=0.5) | 0 |
| macro-F1 | **0.794** | 0.440 |

발표용 단문: **「1년 내 폐업 경고는 95% 적중하고(폐업 정밀도 0.948), 실제
폐업의 절반을 사전에 잡아낸다.」** — 반드시 **«1년 · 자리+점포조건 · 2025
상반기 개업 홀드아웃»** 라벨과 함께 쓸 것. 코호트 전량인 2024 홀드아웃에서는
폐업 정밀도 **0.885** / recall 0.375다(§32-B) — "95%"가 최상 셀의 값임을
알고 말해야 질문에서 무너지지 않는다.

인용 규칙 세 가지(위반하면 심사 질문에서 무너진다): ① 생존 F1은 반드시
베이스라인(0.88)과 병기 — 기저율이 높아 "전원 생존"도 F1 0.88이다. ② 모든
숫자에 기간·정보·홀드아웃 연도 라벨 필수. ③ **추천 순위에 쓰는 성능은
0.6383** — 면적은 사용자가 정하는 점포 속성이라 순위에 넣지 않는다는 원칙은
그대로고, 위 표는 "자리+조건을 알 때 시스템 전체가 얼마나 판별하는가"다.
상세는 `docs/model-findings.md` §32.

### 5.2 M2 — 승계확률

같은 자리에서 앞 임차인이 나간 뒤 **다음 임차인이 공백 없이 들어오는가**를 예측한다. 권리금이 오갔을 가능성의 프록시다.

| 항목 | 값 |
|---|---|
| 코호트 | train 175,401(2005–2021) / calibration 11,736(2022) / **holdout 13,001(2023)** |
| AUC | **0.7443** (업종 베이스라인 0.6139) |
| Brier (보정 후) | **0.1140** (전년도 상수 0.1295) |
| 승계율 추이 | 5.32% → 11.12% → 15.07% |

- 이 값은 **"승계 확률"이지 "권리금 회수율"이 아니다.** 지불 비율의 원천 데이터가 없어서 회수율이라 부를 근거가 없다. 화면도 "승계"라고만 쓴다.
- 보정이 2022년 기저율(11.12%)에 맞춰져 있어 **2023년 체제(15.07%)를 낮게 잡는다.** 절대값보다 순위가 신뢰도가 높다.

### 5.3 모델 선정 — "여러 개를 겨뤄봤다"

후보 6종(로지스틱 · LightGBM · RandomForest · ExtraTrees · HistGB · MLP)을 내부 검증에서 겨루고 홀드아웃으로 확인했다. 결과는 **현행 LightGBM 유지** — 내부 검증 승자(RandomForest)가 홀드아웃에서 1등급 생존율을 −0.12%p [−0.94, +0.98] 움직여 사전 등록한 채택 기준에 미달했다.

```bash
python -m model.test_leakage     # 누수 가드        RED→GREEN
python -m model.asof --selftest-cut   # T 이후 행을 지워도 값 불변
```

**누수 가드가 RED→GREEN인 이유**: 누수가 있는 피처를 일부러 넣어 가드가 **빨간불을 켜는지** 먼저 확인하고, 뺀 뒤 초록불을 확인한다. 가드가 작동한다는 것 자체를 검증한다.

**as-of 복원**: 2015년에 개업한 점포의 등급을 매길 때, 2015년 시점에 알 수 있었던 정보만으로 피처를 다시 만든다. 셀프테스트는 "T 이후 행을 전부 지워도 T 시점 피처값이 변하지 않는가"를 검사한다.

### 6.2 백테스트 결과

- **자치구 24/25**에서 베이스라인 대비 개선 (순수 입지 기준)
- **면적 통제 후에도 입지 효과가 남는다**: 25㎡ 미만 격차 **34.9%p**, 90㎡ 이상 **15.0%p**
  (이 두 값은 **legacy 벤치** — 학습 2005–2018 / 검증 2019–2022 — 의 측정이다.
  배포 계보 수치와 한 표에 이어 붙이지 말고, 인용 시 벤치 라벨을 단다)

> **타깃이 분명하다**: 작은 가게일수록 입지가 중요하다. **자본이 적을수록 이 서비스가 더 필요하다.**

### 6.3 기각한 것 — 이걸 발표에 넣어야 한다

**비정형 데이터로 예측하려는 시도는 아홉 번 전부 기각됐다.** 검색 트렌드 · 점포 언급량 · 트렌드 재검정 · 지명 단위 3종 · 실거래가 · 방문 시간대 · 1인당 지출.

**왜 안 되는지도 쟀다**: 검색 관심도와 실제 유동인구의 상관이 **ρ=+0.079** (CI −0.071~+0.218). 트렌드가 예측을 못 하는 게 아니라, **검색되는 것이 상권의 실제 활동량과 연결되어 있지 않다.**

**도구가 고장난 것은 아니다**: 인허가 업태를 정답으로 놓고 "블로그 글만 보고 업종 맞히기"를 채점했더니 macro-F1 **0.4701**(무작위 0.143). 추출기는 작동한다 — 재료(147자 스니펫)의 한계다.

**검정력도 확인했다**: 트렌드 재검정 최소검출효과 +0.0027 < 임계 +0.005. **못 본 게 아니라 없었다.**

> **슬라이드 메시지**: "비정형 기여를 두 가지 방식으로 측정했고 둘 다 아니었다 — **측정 없이 결합을 주장하는 팀과 방법론적으로 다르다.**"

## 7. 경제성 — "입지 위험의 가격"

등급별 실측 생존곡선을 손익 계산에 곱한다. 기존 창업 계산기는 `초기투자 ÷ 월이익`으로 끝나는데, 그 계산은 **회수 시점까지 가게가 살아있다고 가정**한다.

**매출·비용이 완전히 같아도**, 자리 등급만 다르면:

| | 3년 기대손익 |
|---|---|
| 1등급 자리 | **+360만 원** |
| 9등급 자리 | **−5,638만 원** |
| **차이** | **5,998만 원** — 순수하게 실측 생존곡선에서 나온다 |

⚠️ 이 값은 마진 가정에 민감하다. 마진 20%면 세 등급 모두 적자이고,
30%에서도 9등급은 적자이므로 **가정을 함께 표기**해야 한다.

## 8. 권리금 적정가 리포트

**세상에 권리금 실거래 데이터가 없다.** 신고 의무가 없어서 공적 데이터가 존재하지 않고, 그래서 아무도 만들지 못했다. 우리는 **초과수익 환원**으로 추정한다.

### 8.1 산식

```
무형재산 = Σ(t≤N) [ (이 상권 점포당 매출 − 서울 상권 중간값) × 영업이익률 × 12 / (1+d)^t ]
           음수는 절사 (권리금 0원이 나올 수 있어야 정직하다)
유형재산 = Σ 취득가 × max(0, 1 − 경과연수/내용연수)
적정 참고가 = (무형 + 유형) × 조정계수
출력 = 단일 숫자가 아니라 밴드 + 민감도 표
```

| 파라미터 | 값 | 출처 |
|---|---|---|
| 영업이익률 | **0.0701** | 외식업체 경영실태조사(농림축산식품부·KREI) 2025년 조사 · 서울 7.01% · n=491 · **임대료 차감 후** |
| 할인율 d | **0.08** | 소상공인 대출금리 5% + 사업위험 프리미엄 3% (v1 고정) |
| N (기간) | min(등급별 실측 기대 존속, 임대차 잔여) | 3년 실측 곡선이라 최대 3년 |
| 벤치마크 | 서울 전체 × 동일 업종 **중앙값** (Level 4) | 상권별 점포당 매출의 중앙값 |
| 조정계수 | 1.0 (v1 미적용) | 데이터 기반 조정은 로드맵 |

**영업이익률 주의**: 이전 v1은 0.15였는데 이는 **2019년(코로나 이전) 값**이었다. KREI 시계열은 2019년 15.0% → 2024년 8.7%로 내려간다. 2026년 매출에 2019년 마진을 곱하고 있었다. **7/29 수정으로 참고값이 일괄 53.3% 낮아졌다** — 발표 예시 숫자는 반드시 수정 후 값으로 다시 캡처할 것.

### 8.2 정직한 경계 (반드시 슬라이드에 넣을 것)

- **상권 밖 격자(49.5%)는 리포트를 제공하지 않는다** — "무형재산을 계산할 매출 근거가 없습니다"로 응답한다. NULL을 서울 평균으로 채워 리포트를 만드는 것은 이 프로젝트가 금지한 목업이다.
- **12업태 중 10개만 지원**한다. "기타"와 "외국음식전문점(인도,태국등)"은 서울 상권분석 업종 분류에 대응 항목이 없다. 없는 것을 다른 업종에서 빌려오지 않고 **제공 불가로 표시**한다.
- 초과수익의 해상도는 **상권 단위**다. 같은 상권 안의 자리끼리는 무형재산이 같게 나온다는 것을 리포트에 표기한다.

### 8.3 서사 프레이밍

> "권리금 실거래 데이터가 세상에 없어서 아무도 못 만들었다 → 수익환원으로 추정가를 만들고, 거래가 쌓이면 시세가 된다 — **KB시세가 아파트에서 밟은 경로를 점포에서 반복한다.**"

## 9. 기술 스택 · 아키텍처

```
[수집]   서울 열린데이터 · data.go.kr · SGIS · 카카오 로컬
            ↓ (일일 900콜 제한 · 인허가 한 종만 536콜)
[파이프라인] Python 3.11 · 18단계 · pipeline/cache/ 캐시
            ↓
[DB]     SQLite (kb.db) — 단일 파일, 읽기 전용 서빙
            ↓
[모델]   LightGBM · scikit-learn · 사전계산 배치
            ↓  grid_score / succession_score 241,776행
[API]    FastAPI — 조회 + 산술만. 모델을 적합하지도, 호출하지도 않는다
            ↓
[UI]     React + Vite + TypeScript · TanStack Query · MapLibre 지도 (역지오코딩만 카카오 로컬 API)
```

| 레이어 | 선택 |
|---|---|
| 언어 | Python 3.11+ / TypeScript |
| API | FastAPI |
| DB | **SQLite** (단일 파일) |
| ML | LightGBM · scikit-learn |
| 좌표 | EPSG:5179 (격자) · 4326 (표시) |
| 프론트 | React + Vite + TanStack Query |
| LLM | 근거 문장 생성 전용 (`/report`) |

> **왜 SQLite인가**: 데이터가 이미 파이프라인 전체에서 SQLite에 있고, 서빙은 **읽기 전용 단일 프로세스**라 동시 쓰기라는 유일한 약점이 발생하지 않는다. 심사 환경에서 설치 없이 도는 것도 이점이다. (기획안의 PostgreSQL 4-Layer 그림은 실물과 다르므로 **아키텍처 슬라이드를 이 그림으로 교체할 것.**)

### 9.2 LLM의 역할 — "숫자는 ML, 설명은 LLM"

- LLM은 **문장만** 만든다. 숫자는 전부 모듈이 계산한 값을 주입한다.
- 프롬프트에 넘기는 것은 **실피처·실측치 구조체뿐**이고, 그 외 정보 주입은 금지다.
- 실패하면 에러를 노출한다 — 목업이나 폴백으로 채우지 않는다.

## 10. 반드시 함께 말해야 할 한계

발표에서 먼저 말하면 강점이 되고, 질문받고 답하면 약점이 된다.

1. **1등급 자리에서도 약 20%가 3년 내 폐업**한다. 9등급에서도 10.1%는
   살아남는다(n=317, 95% CI 7.2–13.9%). **입지는 일부일 뿐이다.**
2. **AUC 0.6383은 가장 어려운 과제(3년 · 순수 입지)의 값**이다. 계약기간(1년)
   과제에서는 0.81~0.84까지 오른다(§5.1-B). 다만 어느 숫자든 "잘 맞힌다"가
   아니라 "베이스라인보다 얼마나 낫다"로 읽어야 한다.
3. **검증된 예측은 100m 격자에서 멈춘다.** 건물·층 단위는 사실과 서울 전체 통계로만 제공하고, 등급처럼 검증된 예측이 아니라고 화면에 명시한다.
4. **매출 데이터는 상권 단위**다. 같은 상권 안의 격자끼리는 그 피처에서 동점이 된다.
5. **상권 밖 49.5%는 매출 기반 기능(부담률·권리금)을 제공하지 않는다.**
6. **M2는 승계 확률이지 권리금 회수율이 아니다.**
7. **코로나가 입지의 측정 가능한 가치를 눌렀다.** 배포 계보 진단에서
   2019–2022 검증 십분위 격차는 30.6%p, 2023 코호트는 47.7%p다(README와 동일
   계보 — 선별 벤치의 31.7↔48.4%p와 섞어 쓰지 말 것).
8. **생존 라벨은 행정 인허가 상태다.** 폐업신고 지연분은 생존으로 집계되므로
   최근 코호트일수록 생존율이 같은 방향으로 과대추정될 수 있다(방향 기지 —
   `docs/data-inventory.md`). 폐업 정밀도 쪽은 보수적으로 작용한다.
9. **홀드아웃은 연도 단위 단일 코호트다.** 2023은 1~7월 개업분(계절 편중)이라
   격차류 절대값은 한 코호트의 추정치로 읽는다. 홀드아웃 AUC의 표준오차는
   ≈0.003(95% CI ≈ ±0.006)이다 — 소수 넷째 자리 차이를 성능 차이로 읽지 않는다.
10. **미확보 데이터**: 공정위 창업비용 · 부동산원 상권 구획도 · 집계구 경계. (R-ONE 임대료·권리금과 VWORLD 물리입지는 확보했으나 공간해상도가 격자보다 거칠어 **표기 전용**이고 점수·순위에는 안 들어간다. 자치구 단위 권리금은 원천 자체가 시도 단위라 존재하지 않는다.)
