# 권리금 리포트 + 해상도 사다리 — 통합 설계

작성 2026-07-27 · 원안: `docs/최지연의 부동산공부방*.md` (이하 "원안") · 이 문서는 원안을 **현재 검증된 스택 위에** 올리는 조정안이다. 원안의 산식·프레임은 대부분 채택하고, 우리가 이미 가진 것으로 대체 가능한 모듈과 마감 내 불가능한 모듈을 가른다.

## 1. 원안에서 그대로 채택 (수정 없음)

- **법정 3분할 산식**: 적정 권리금 = 무형(수익환원) + 유형(원가법) × 조정계수. 상가임대차보호법 10조의3 구조를 따른다는 프레이밍 포함.
- **초과수익 정의**: 권리금 = "아무 데나 열었을 때보다 더 버는 부분"의 값. **음수 절사(권리금 0원이 나올 수 있어야 정직)**.
- **동급 상권 군집화의 순환논리 금지**: 군집 변수에 매출·폐업률 절대 금지, 구조 변수만. 벤치마크 계층 폴백(Level 1~4) + 사용 레벨 표기.
- **N = min(기대 존속기간, 임대차 잔여 보장기간)**.
- **밴드 산출**(단일 숫자 금지) + **민감도 표**를 리포트에 정면 배치.
- **증권사 리서치 포맷** (협상 참고등급 / 호가 / 추정가 / 괴리율 / 밴드 / Valuation 분해 / 강점·리스크 / 근거 출처 / 하단 고지).
- **용어 금지어**: "감정가"·"투자의견"·"권리금 담보(대출)". → "추정 참고가"·"협상 참고등급"·"KB 적정가 검증 통과 거래에 한한 신용대출 우대".
- **LLM 역할 분리**: 숫자는 모듈, LLM은 문장만 — 기존 `/report` 숫자 화이트리스트 규칙 그대로 적용.
- **학습/계산 구분 선언** (원안 §0): 권리금 산식은 학습이 아니라 계산. 발표 문장 그대로 사용.

## 3. 커버리지의 정직한 경계

- 매출 데이터는 **상권 내 격자(53.2%)만** 존재 → **상권 밖 자리는 권리금 리포트 제공 불가**로 명시("무형재산을 계산할 매출 근거가 없습니다"). NULL을 서울 평균으로 채워 리포트를 만들지 않는다 — 목업 금지의 권리금 버전.
- 초과수익의 해상도 = 상권 단위. 같은 상권 안 매물끼리는 무형재산이 동일하게 나온다는 것을 리포트에 표기(단위 캡션 규칙 재사용).
- 원안 숫자 예시(1,900만·75만·5,200만)는 전부 목업 — 화면·발표에 쓰지 않는다.

## 4. Module A 동급 상권 군집화 — 신규 작업 (레인 A)

원안 §3을 스펙으로 채택하되 마감 규모로 축소: 구조 변수만(유동·상주·직장·시설·접근성·점포 구성) · k=6~8 · 전처리(log1p·구성비·표준화·관광특구 분리) · **검증 3종 = 실루엣 ≥0.25 · 매출 미사용 군집의 매출 설명력 η² ≥0.2 · 부트스트랩 ARI ≥0.6**. η² 검증은 사전 등록 실험(**E6**)으로 `experiment-plan.md`에 편입 — 통과하면 발표 최강 슬라이드("구조가 매출을 설명한다"), 실패하면 권리금 리포트는 로드맵으로 강등하고 실패를 기록한다.

## 5. 해상도 사다리 — "건물·층 단위" 요구의 정직한 해법

건물·층 단위 **랭킹 추천**은 못 한다(검증된 예측이 격자까지). 대신 **검증 등급 위에 사실 정보를 쌓는 사다리**로 내려간다:

```
격자 (100m)   입지 등급 + 실측 생존율          ← 검증된 예측 (홀드아웃)
  └ 건물      건축물대장(용도·연면적·연식·층수) ← 사실
             + 상가업소정보(건물 내 테넌트 구성) ← 사실
  └ 층        업종×층별 서울 실측 생존율 통계    ← 통계 참고 (개별 검증 아님)
```

- **건물 진단 카드** (B 진단 모드 확장): 주소 입력 → 격자 등급(검증) + 이 건물의 사실(연식·용도·층수·현재 입점 업종 구성) + "이 건물 1층에 {업종} — 층별 서울 실측 생존율 {n}%" 참고 통계. 라벨 필수: **"건물·층 수준은 사실과 서울 전체 통계이며, 등급처럼 검증된 예측이 아닙니다."**
- 데이터: 건축물대장 표제부(공공 CSV) + 소상공인 상가업소정보(층 필드 보유 — README의 지하 59.8/1층 66.2/2층 69.9가 이 소스). 둘 다 점 단위라 공간해상도 원칙과 충돌 없음. 상가정보는 키 연계 문제(업종 개편·번호 재생성)가 있어 좌표+상호 매칭 전처리 필요 — **마감 내면 P2, 아니면 로드맵**.
- 원안의 임대인 사이드(테넌트믹스 추천·공실 조기경보·적정 임대료·건물가치 시뮬)는 원안 판단대로 **로드맵 유지** — 단 기술설명서에서 "같은 엔진을 뒤집으면 양면시장"이라는 확장 논리로 1장 쓴다.
- 매물 단위는 변함없이 KB부동산 연계 전제의 스케일업 과제.

## 6. 산출 흐름 (v1 확정)

```
입력: 자리(격자/주소) · 업종 · 호가 권리금 · 임대차 잔여기간
      · (유형) 인테리어/설비 취득가·경과연수

무형 = Σ_t≤N [ (상권매출−군집벤치마크)×영업이익률 ×12 / (1+d)^t ] , 음수 절사
       N = min(등급 실측 생존곡선 기대 존속, 임대차 잔여)
       d = 소상공인 대출금리 + 프리미엄 (근거 명시·고정)
유형 = Σ 취득가 × max(0, 1−경과/내용연수)
적정가 = (무형+유형) × 조정계수(모멘텀 항 제외판, ±25% 캡)
출력 = 밴드(r±3%p · N±1년 · d±2%p 그리드의 5~95백분위) + 민감도 표 + 협상 참고등급
```

영업이익률 r은 소상공인실태조사 업종별 값(출처 표기). `economics`의 "임대료 차감 전 마진" 이중 차감 교훈을 여기도 적용 — r의 임대료 포함 여부를 구현 전에 확정하고 주석으로 박는다.

## 7. 스코프 결정 (마감 8/3)

**구현은 E6과 병행한다 (2026-07-27 확정).** E6은 스코프 관문이 아니라 **벤치마크 선택기**다 — 산식·엔드포인트·화면은 벤치마크 그룹이 무엇이든 동일하므로 병행이 안전하다:

- E6 **통과** → 벤치마크 = 동급 군집 × 업종 (Level 1~3), 발표에 η² 슬라이드.
- E6 **실패/미완** → 벤치마크 = **서울 전체 × 동일 업종 (Level 4)**으로 자동 강등 + 리포트에 "동급 상권 비교가 아닌 서울 업종 평균 대비" 명시 + negative 기록. 리포트는 죽지 않고 주장의 강도만 낮아진다.
- 어느 쪽이든 **사용된 벤치마크 레벨을 리포트에 표기**(원안의 폴백 규칙이 이 상황을 이미 커버한다).

| 항목 | 판정 |
|---|---|
| Module A 군집 + E6 검증 | 레인 A, 7/29~30 — 결과는 벤치마크 레벨 결정 |
| 권리금 산식 + `/goodwill` 엔드포인트 | 레인 B, **P1 — 즉시 착수 가능** (벤치마크는 레벨 파라미터로 추상화해 구현) |
| 리포트 화면 (증권사 포맷) | 레인 C, **P1** — `ui-spec.md` 컷라인에 반영 |
| 건물 진단 카드 (건축물대장+상가정보) | **P2 / 로드맵** — 전처리(키 매칭)가 30% 작업량이라는 원안 경고 존중 |
| 매출 예측 모델 · 임대인 사이드 · 에스크로/시세화 2단계 | **로드맵 전용** — 기술설명서에서 "추정가는 시세의 씨앗, KB시세가 아파트에서 밟은 경로" 서사로 |

## 8. 서빙·화면 확정 (2026-07-27 — F-C1 해소 설계)

E6은 사전 등록 검증에 실패했으므로(실루엣 0.1175 · η² 0.1327) §7의 자동 강등이 발동한다:
**벤치마크 = Level 4 (서울 전체 × 동일 업종) 고정**, 리포트에 레벨 명시.

### 8-A. 파라미터 소유권 — 입력 슬림다운 (계약 개정)

현행 `GoodwillInput`은 벤치마크·마진·할인율을 호출자가 전달하게 돼 있다. 그러나 이
값들의 정직한 생산자는 전부 서버다(벤치마크=DB 집계, r=소상공인실태조사 상수,
d=명시 상수). 호출자 전달은 pass-through만 만들고, 프론트가 값을 창작할 수 없어
호출 자체가 불가능했다(`findings.md` F-C1). **개정: 서버 내부 계산으로 옮기고
입력은 사용자 몫만 받는다.**

```ts
// 개정 GoodwillInput — 사용자가 아는 값만
{
  gridId: string;
  uptae: string;
  askingGoodwill: number;      // 호가 (만원) — 사용자
  leaseRemainingYears: number; // 임대차 잔여 (년) — 사용자
  assets?: Array<{ name, acquisitionCost, ageYears, usefulLifeYears }>; // 유형 — 사용자
}
```

| 값 | 소유 | 원천 (서버가 응답에 출처 필드로 되돌려준다) |
|---|---|---|
| M 상권 매출 | 서버 | 해당 상권×업종 점포당 월 추정매출 (economics의 서울 평균과 같은 원천 테이블, 상권 단위 캡션) |
| M̄ 벤치마크 | 서버 | 서울 전체 × 동일 업종 점포당 월 추정매출, `benchmarkLevel: 4` 고정 |
| r 영업이익률 | 서버 | 소상공인실태조사 업종별 값 — **임대료 차감 후** 기준(§6 교훈), `operatingMarginSource` 명시 |
| d 할인율 | 서버 | 소상공인 대출금리 + 리스크 프리미엄, `discountRateSource` 명시 |
| 조정계수 | 서버 | **v1 = 1.0 고정** + `adjustmentReasons: ["v1 미적용 — 데이터 기반 조정 항은 로드맵"]`. 검증 안 된 항을 곱하지 않는다(§2 모멘텀 제외와 같은 원리) |

`GoodwillResponse`는 무변경 — 이미 모든 기반값·출처·밴드·민감도를 되돌려준다.
서버는 기존 풀 입력 함수를 내부에 유지하고, HTTP 계층에서 기반값을 채워 호출한다.

### 8-C. 화면 — S4 "권리금 협상 리포트" 섹션 (증권사 리서치 포맷)

리포트 시트의 경제성 카드 아래 섹션. 구조는 §1의 포맷 채택 항목을 그대로 편성:

1. **입력 행**: 호가(만원) · 임대차 잔여(년) · [+ 유형자산 추가] (이름·취득가·경과/내용연수 행 추가식). 디바운스 후 POST.
2. **헤드라인**: 협상 참고 필(`below_band` "호가가 참고 밴드 아래" 녹 / `within_band` "참고 밴드 안" 회 / `above_band` "참고 밴드 위 — 협상 여지" 주황) + **추정 참고가 n만** + 밴드 `n만 ~ n만` 병기.
3. **괴리 행**: 호가 | 추정 참고가 | 괴리 `±n만 (n%)`.
4. **Valuation 분해**: 무형 n만 + 유형 n만 (조정계수 1.0 — 미적용 표기). 유형자산 표는 입력 시만.
5. **근거 행렬**: M(상권 단위 캡션) · M̄("서울 전체 × 동일 업종 — Level 4" 명기) · r(출처) · d(출처) · N = min(기대 존속 n.n년, 잔여 n년) — 전부 응답 필드에서.
6. **민감도 표**: `sensitivity` 그대로 (마진·존속·할인율 축).
7. **고지**: `notice` 서버 문장 그대로 + 단위 캡션 "무형재산은 상권 단위 — 같은 상권 안 자리는 동일".

카피 규칙: "감정가"·"적정가" 단독 표기 금지 → **"추정 참고가"**. 등급 포맷·금지어는 `ui-spec.md` §4 그대로.
