# UI에 제공 가능한 데이터 — 스펙 협의용

작성 2026-07-26 · **이 문서는 "우리가 줄 수 있는 것"의 목록이지 화면 설계가 아니다.**
UI 스펙이 확정되면 그에 맞춰 조회 계층을 붙인다. 협의 시 이 목록을 재료로 쓸 것.

## 이미 계산되어 즉시 조회 가능

`kb.db` / `grid_score` 테이블 — **241,776행 (12개 업태 × 20,148격자)**, 전체 재계산 84초.

## 화면에 반드시 함께 노출해야 하는 것

정확도를 부풀리면 심사에서 무너진다. 아래는 협상 대상이 아니다.

1. **1등급 자리에서도 약 20%는 3년 내 폐업한다.** 9등급도 10.1%는 살아남는다(n=317, 95% CI 7.2–13.9%).
2. **모델 성능은 AUC 0.6383** — 무작위보다 나은 수준이지 "잘 맞힌다"가 아니다.
3. **매출이 없는 격자는 "없음"으로 표기** — 0으로 그리면 최악의 입지처럼 보인다. 격자의 49.5%가 여기 해당한다.
4. **행정동/상권 단위 값에는 그 단위를 표기.**
5. **점포 면적·층은 순위에서 제외**됐다. 면적은 별도 정보로 유용하다(25㎡ 44.8% ↔ 90㎡+ 74.4%). 층별 생존율은 인용하지 않는다 — 종전 세 값은 F-A5에서 폐기됐고, 층 차이로 보이던 것은 면적이었다.

## 스펙 확정 시 필요한 정보

1. **화면 구성** — 지도 중심인가, 목록 중심인가, 조건 입력 폼이 먼저인가
2. **입력 항목** — 업태 외에 예산·면적·희망지역을 받는가
3. **호출 방식** — HTTP API(FastAPI 가능), 정적 JSON 파일, 아니면 직접 DB 조회
4. **지도 라이브러리** — 카카오/네이버 지도 키는 이미 있음(`KAKAO_JAVASCRIPT_KEY`는 미발급)
5. **격자 표출 방식** — 점, 사각형 폴리곤, 히트맵 중 무엇인가

`service/api.py`에 조회 함수 초안이 있으나 **스펙 확정 전이라 형태는 확정 아님**. HTTP 계층은 협의 후 작성한다.
