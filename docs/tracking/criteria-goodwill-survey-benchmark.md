# 수용 기준: 권리금 공표통계 자동 수집·추출 파이프라인 (외부 대조군)

작성 2026-07-30 · 발단: `service/goodwill.py` 의 추정가에 **외부 정답이 0개**라 밴드·민감도가 전부 산식 내부 자기참조다. 서울시 상가임대차 실태조사가 상권별·업종별 권리금을 공표하므로 이를 대조군으로 들인다.

목표: 서울시 상가임대차 실태조사 PDF에서 권리금 표를 **자동으로 받아 추출하고, 문서에 인쇄된 검산식으로 검정한 행만 채택해**, 우리 권리금 추정가의 자릿수·분포를 외부 기준과 대조한다.

**설계 변경 (2026-07-30)**: 표 종류 판정을 모델에게 맡겼더니 상권별 표를 `uptae` 로
오분류하고, 8장 배치에서는 전 페이지 null 을 반환했다. 모델은 **제목·머리글·행
라벨을 그대로 옮기기만** 하고 분류는 `classify()` 가 한다. 제목까지 읽어야 하는
이유: 2022 업종별 표의 컬럼은 금액 구간이라 「권리금」이 캡션에만 있다.

### C. 추출 + 검정 (핵심 위험)

- [x] 상권별 표 추출 결과가 인쇄된 검산식을 통과한다 — `계 = 보증금 + 권리금 + 시설투자비`, 허용오차 ±1 만원(반올림)
  → verify: `--extract 2023 --table trdar` → exit 0 · 채택 125행 · 검산 탈락 0
- [x] 업종별 표 추출 결과가 구간 백분율 합 = 100 (±0.3) 을 통과한다
  → verify: `--extract 2022 --table uptae` → exit 0 · **10/10 채택 · 재추출 불일치 0 · 검산 탈락 0**. 값이 육안 판독과 일치
- [x] **검산 실패 행은 채택하지 않는다.** 값을 고치거나 추정해 채우지 않고, 탈락 행을 명시한다
  → verify: `python -m pipeline.test_sftc` → exit 0 · 23/23. 실데이터에서도 작동 — 1차 추출의 학동역 시설투자비 5,264(실제 5,254)를 `검산 불일치 +10.00` 으로 탈락
- [x] 추출 산출물은 JSON 아티팩트가 원본이고 DB 는 파생이다
  → verify: `pipeline/cache/sftc/sftc-2023-trdar.json` 존재

**검산의 한계 — 실측으로 드러남 (2026-07-30).** 검산은 **자릿수 오독은 잡지만 조작은
못 잡는다.** 2023 p.27 을 통째로 보냈을 때 모델이 그 페이지에 없는 자치구(성동구·
영등포구·용산구 등)의 행을 지어냈고, **지어낸 행들이 계 = 합을 만족했다** — 모델이
스스로 맞춰 만들기 때문이다. 대응 둘:

1. **독립 재추출 일치** (`agree`, 기본 2패스) — 인쇄된 숫자는 반복되고 지어낸 값은
   반복되지 않는다. p.27 일치율 21/77 로 불안정이 드러났다.
2. **블록 슬라이싱** (`render_slices`) — 한 장에 66행을 담아 보내면 비전 API 가
   다운샘플한다. 페이지를 세로 3블록으로 잘라 행당 해상도를 유지한다.
   p.27 일치 21 → 60, 전체 채택 85 → 125행.

구조 검정 통과: **p.27 과 p.28 의 자치구 교집합이 공집합**(p.27 강남~서대문 / p.28
서초~중구)으로, 인쇄된 가나다 배치와 일치한다. 유령 행이 사라졌다는 증거다.

**남은 결손**: 125/145 상권(86%). 노원·도봉·동대문·동작·중랑 5개 구가 통째로
빠졌다 — 슬라이스 경계에 걸린 블록으로 보인다. 채워 넣지 않고 결손으로 둔다.
