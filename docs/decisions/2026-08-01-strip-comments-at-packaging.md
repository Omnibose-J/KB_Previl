# 출하 주석은 소스를 고치지 않고 패키징 때 걷어낸다

**Decision:** 2026-08-01. 제출 zip 에 들어가는 `.py`·`.ts`·`.tsx` 는
`tools/strip.py` 가 빌드 시점에 주석과 독스트링을 전부 제거한 사본으로 넣는다.
저장소 소스는 그대로 둔다. 모듈마다 `tools/manifest.py:HEADERS` 의 영어 한 줄만
새 독스트링으로 주입한다.

**Context:** 소유자가 «출하 코드에 설계 의도 주석이 없을 것, 진짜 최소한의 기능·
섹터 구분 주석만» 을 요구했다. 첫 측정에서 위반이 **368건 · 73개 파일**이었고
파이썬 주석·독스트링만 3,524줄이었다. 마감까지 이틀이었다.

**Why:**
- 손으로 73개 파일을 고치면 **동작하는 코드를 마감 직전에 대량으로 만지게 된다.**
  주석만 지운다는 보장이 없고, 잘못 지운 것을 되돌릴 방법도 없다.
- 기계적 제거는 검정 가능하다. 벗겨낸 트리에 기존 서빙 계약 121종을 그대로
  돌려 `121 passed / exit 0` 을 얻었다(`tools/audit.py --behaviour`). 손으로
  고쳤다면 이 검정은 «내가 안 망가뜨렸다» 는 주장에 불과했을 것이다.
- 저장소가 연구 기록을 잃지 않는다. 왜 그렇게 짰는지가 남아 있어야 다음 사람이
  같은 함정을 다시 밟지 않는다. 출하물과 작업 기록은 독자가 다르다.
- 되돌리기가 싸다. 마음이 바뀌면 `strip.py` 를 안 쓰면 그만이다.

**Rejected:**
- *73개 파일을 손으로 정리* — 위 이유. 되돌릴 수 없고 검정할 수 없다.
- *주석을 전부 남기고 조건을 협상* — 소유자가 세 번 반복해서 요구한 조건이다.
- *서사 주석만 골라 자동 분류* — «설계 의도» 와 «기능 설명» 의 경계를 기계가
  안정적으로 못 가른다. 애매한 것을 남기면 조건 위반이고 지우면 정보 손실이다.
  전부 지우고 모듈당 한 줄을 새로 쓰는 쪽이 결과가 예측 가능하다.

**Status:** Active. 관련 계약은 [[criteria-submission-repack-v1]],
면제 판단은 [[2026-08-01-size-exempt-over-threshold]].
