### 원칙 6 — 모든 화면 결정의 상위 규칙

1. **한 화면 한 질문.** S2는 "어떤 가게를 어디서?"만, S3는 "어디가 좋은가?"만, S4는 "이 자리 들어가도 되나?"만. 한 화면이 두 질문에 답하려 하면 분리한다.
2. **숫자보다 문장 먼저.** 모든 핵심 수치는 사람 문장으로 번역해 숫자보다 크게 싣는다: "이 등급 자리 100곳 중 74곳이 3년을 버텼습니다" ← 옆에 작게 "74.3% (홀드아웃 실측)". 토스 UX writing의 User-side info / Weed cutting 원칙을 따른다 — 모델 용어(AUC·홀드아웃·십분위)는 본문에서 금지, 툴팁으로. **예외 — 비협상 공시 2줄**("상위 10%도 약 26% 폐업", "AUC 0.59 = 무작위보다 나은 수준")은 §4 고정 한계 스트립으로 화면에 노출한다. 별도 방법론 페이지는 만들지 않는다 — 상세는 S4 데이터·한계 카드와 툴팁이 담당.
3. **입력은 2개로 시작.** 업종 + 지역이면 결과가 나온다(등급은 사전계산). 임대료·초기투자·매출·마진은 **결과를 본 뒤** 경제성 카드에서 인라인으로 — 폼 4단계(STEP 1~4)를 미리 다 채우게 하지 않는다. S2는 사실상 "업종·지역 선택 + 선택적 예산 한 줄"로 압축된다.
4. **지도가 곧 내비게이션.** 호갱노노처럼 지도 위 격자가 1차 정보(등급 색 + 탭하면 요약 말풍선)이고 목록은 보조다. 목록 hover ↔ 지도 하이라이트 동기화(Zillow 패턴).
5. **화면당 옐로우 강조 1곳.** 브랜드 옐로우는 CTA와 1등급 표시에만. 상태·경고는 시맨틱 컬러(녹/주황/회색)로 분리.
6. **"모른다"를 디자인 요소로.** NULL 빗금, partial 배지, "이 값은 동 단위" 캡션 — 불확실성 표기가 서비스의 차별점이므로 숨기지 않고 스타일을 준다.

## 1. 스펙 5문 확답 (`ui-data-contract.md` § 스펙 확정 시 필요한 정보)

| 질문 | 결정 | 이유 |
|---|---|---|
| 화면 구성 | **최소 입력 → 지도 우선 + 목록 보조(S3)** | 지도 격자가 1차 정보(§0 원칙 4), 목록은 랭킹·근거 보조 |
| 입력 항목 | 필수 = **업종 + 범위**. 선택(S2 접힘) = 월 임대료·초기투자. 매출·마진·면적·층은 **S4 인라인 입력** | **범위 = 자치구 다중선택(서울 전역 포함). 반경 개념 없음** — 백엔드는 자치구 필터만 지원. 면적·층은 순위 미반영·참고 정보로만 |
| 호출 방식 | **HTTP API (FastAPI)** 요청. **목업 데이터·폴백 금지** — C는 처음부터 실 API만 소비하므로 B의 최소 엔드포인트(격자 조회·랭킹)가 C 착수의 선행 조건 | What-if 재계산·진단 플로우가 정적 파일로는 안 됨. 목업 수치는 실측과 어긋난 채 살아남는 사고 전례(시안 목업)가 있다 |
| 저장소 | **SQLite(`kb.db`) 유지 — PGlite 도입 반대** | 근거는 표 아래 |
| 지도 라이브러리 | 1순위 **카카오 지도 JS** (`KAKAO_JAVASCRIPT_KEY` 발급 선행 — 무료·즉시) · 발급 지연 시 **MapLibre GL + OSM** 폴백 (키 불요) | 네이버 JS 키 보유 여부 미확인. 폴백은 키 리스크 제거용 |
| 격자 표출 | **100m 사각형 폴리곤** (줌 ≥14) · 줌아웃 시 셀 그대로 축소 렌더(뷰포트 셀 수 상한으로 제어) | 점·히트맵은 "100m 격자"라는 해상도 주장을 시각적으로 못 지킨다. **행정동 코로플레스는 불가** — 경계 shapefile 미확보(`ui-data-contract.md` 줄 수 없는 것) |

API에 추가로 요구할 것 (전부 §7 부록의 엔드포인트 표에 반영):
- 격자 폴리곤 꼭짓점의 **위경도 변환은 B가 제공**(EPSG:5179 노출 금지) · `score_meta`의 등급별 실측 생존율·CI 동봉.
- **뷰포트 조회 `GET /grids?uptae&bbox`**(셀 수 상한 포함) — 지도 우선 내비게이션(§0 원칙 4)의 전제. 현행 `recommend()`는 자치구+top뿐이라 지도 이동 갱신이 불가능하다.
- **격자별 `openings_36m`·`churn_36m` 컬럼 신설 — 레인 A 선행.** 현재 `grid_feature`에는 누적 개폐업뿐이라 "검증된 자리/과열 신호" 필·칩·기여 바가 쓸 데이터가 없다. 기준시점 = `score_meta.as_of`. **8/1까지 미확보 시 해당 필·칩은 누적 개폐업·영업 점포 수 기반 문구로 축소**한다(추정치 창작 금지).
- 면적 5구간 실측 생존율을 `score_meta`에 추가(면적 참고 카드의 출처 — 프론트 하드코딩 금지 원칙 유지. 층은 원천에 필드가 없어 제외).
- 위치 앵커의 방위(bearing)는 B가 계산해 제공. 없으면 "성수역 180m"처럼 거리만 표기(방위 창작 금지).
- `api.py`의 한계 문구 상수("약 27%")를 §4-C 기준("약 26%")으로 갱신 — 화면 문구는 전부 API에서 오므로 여기가 낡으면 화면이 낡는다.

**SQLite vs PGlite 판단**: ① 데이터가 이미 SQLite다 — 파이프라인·모델·precompute 전부 `kb.db` 계약이라, PGlite는 229MB 마이그레이션 + 변환 파이프라인이라는 새 고장 지점을 만들고 얻는 게 없다. ② 서빙 워크로드가 읽기 전용·단일 프로세스(쓰기는 레인 A precompute뿐)라 SQLite의 유일한 약점(동시 쓰기)이 해당 없다. ③ PGlite는 JS 런타임에 임베드하는 Postgres-WASM(단일 연결)이라 FastAPI(Python)와 접점도 없고, 브라우저에 싣는 용도라면 229MB를 내려보낼 수 없어 성립하지 않는다. PGlite를 다시 고려할 유일한 시나리오는 "백엔드 없이 브라우저 단독 데모" 요구가 생길 때인데, 그때도 `grid_score` 추출본을 sql.js(SQLite-WASM)로 싣는 쪽이 변환 없이 곧다.

**목업·폴백 금지 (전 화면 공통)**: 로딩·에러·빈 결과는 각각의 명시적 상태로 그린다. API 실패 시 가짜 값·캐시된 예시·"대략 이 정도" 표시로 채우지 않는다 — 실패는 보이게 실패한다.

## 2. 플로우 — 진입 2모드

```
A. 자리 찾기(탐색):  S1 → S2 조건 입력 → S3 목록+지도 → S4 상세 리포트
B. 이 자리 어때?(진단): S1 → 주소/지도 클릭 → S4 상세 리포트 (S2·S3 건너뜀)
```

**B 모드를 추가하는 이유**: 실사용자 다수는 이미 매물을 보고 있고, 그 매물의 임대료를 안다(임대료를 데이터로 채우지 않는 원칙과 정합). 백엔드는 `pipeline.query`(좌표→격자)로 이미 지원한다. S1 검색 카드를 탭 2개로 나눈다: `자리 찾기` / `이 자리 어때?`(주소 입력창 1개).

- S4는 두 모드의 공용 화면. B 모드에서는 브레드크럼이 "진단 결과"로 바뀌고 "결과 목록으로"가 없다.
- S2의 스텝 인디케이터(조건→분석→확인)는 A 모드 전용. 유지.
- 시안의 "비교함"(S3·S4)은 유지 — 격자 2~3개 나란히 비교는 등급·실측 생존율 표가 이미 지원한다.

## 3. 화면별 — 시안에서 달라지는 것

### S1 랜딩

6섹션 골격은 참고만 한다. **기능 카드는 6장 → 3장으로 통합**(①실측으로 검증된 등급 ②검증된 자리 vs 과열 신호 ③입지 위험을 반영한 손익) — 시안의 ②동적 가중치·④경쟁 분석은 ①②에 흡수, 크기 위계를 주어 균질 그리드를 깬다(§0). 다크 배경은 히어로 1곳만. 콘텐츠 교체:

| 위치 | 시안 | 교체 |
|---|---|---|
| Hero 서브카피 | "예상 월매출·손익분기·3년 생존확률과 근거" | "인허가 53.5만 건(1980년대~)에서 뽑아 **시간분리 검증(학습 2005~2022 / 검증 2023)한 입지 등급**과, 그 등급 자리들의 **실측 3년 생존율**" — "13년 백테스트" 같은 뭉뚱그림 금지(원자료 기간과 검증 기간을 섞으면 §0이 금지한 과장) |
| Hero 검색 카드 | 보증금+월세/업종/범위/오픈예정 4필드 | 탭 2개(§2). `자리 찾기` 탭 = 업종·범위 2필드만(예산은 S2에서). `오픈 예정` 삭제 — 시점 차원이 모델에 없다 |
| 데이터 출처 스트립 | 인스타·블로그·리뷰 포함 | 실제 사용분만: 인허가 이력·서울 상권매출·생활인구·센서스·지하철. 비정형 언급 삭제 |
| 기능 카드 ① SNS 선행지표 | 전면 교체 → **"실측으로 검증"**: 상위 10% 자리 실측 생존율 vs 하위 10% (시간분리 홀드아웃) | 비정형은 측정 결과 기여 없음 — 주장하면 심사에서 무너진다 |

### S2 조건 입력

**시안의 STEP 1~4 폼을 해체한다** (§0 원칙 3). 기본 화면 = **업종 선택 + 지역 선택 + CTA** 한 덩어리. 예산은 "예산도 입력하면 손익까지 계산합니다" 접힘(아코디언) 한 줄로 — 펼치면 초기투자·월 임대료 2필드. 매출·마진·면적·층은 S2에서 받지 않고 **S4 경제성 카드에서 인라인 입력**한다. 요약 패널·퍼널은 유지(실값). 세부 결정:

| 항목 | 결정 |
|---|---|
| 예산 (접힘) | `초기투자 총액`(보증금+권리금+인테리어 합산 안내)과 `월 임대료` 2개. economics 입력과 1:1 대응 |
| 업종 | 칩을 **실제 12업태**로 교체(한식·호프/통닭·경양식·분식·일식·중국식·외국음식·정종/대포집/소주방·통닭·식육·까페·기타). "브런치 카페" 등 가공 업종 삭제. 가중치 노트("주말 유동↑↑…")는 근거 없음 — 삭제하고 "업태별로 별도 스코어를 사전계산했습니다"로 교체 |
| 지역 | "성수·연남·홍대 파일럿" 문구 삭제 — **자치구 25개 전부** 커버가 사실이고 더 강하다. 칩 = 서울 전역 + 자치구 25 드롭다운. "지도에서 직접 그리기"는 v2 범위 외(폴리곤 교차 연산 비용 대비 데모 가치 낮음) — 칩 삭제 |
| 창업자 프로필 | **삭제.** 자기자본·경험·리스크 성향은 모델에 입력되지 않는다 — 받으면 반영하는 척이 된다 |
| 매출·마진·면적·층 | S2에서 받지 않는다 → S4 경제성·참고 카드의 인라인 입력으로 이동. 면적·층은 입력 시점에 "순위에 반영되지 않습니다 — 등급은 자리의 것, 면적은 사장님의 선택" 명시 |
| 요약 패널 퍼널 | "12,480 블록→842→24" → 실값: **20,148 격자 → 범위 내 N → 등급 상위 N'**. 값은 전부 API 응답에서 — 화면 하드코딩 금지 |

### S3 결과 대시보드

2컬럼 배치는 참고하되 **주도권을 지도로** 옮긴다(§0 원칙 4): 격자 탭 → 말풍선(등급 + 사람 문장 1줄, 예: "1등급 — 100곳 중 74곳이 3년을 버틴 자리"), 목록 hover ↔ 지도 하이라이트 동기화, 지도 이동 시 목록 갱신. 핵심 교체는 **카드 지표 4종과 지도 탭**:

**후보 카드** — 지표 행을 다음 4칸으로:

| 칸 | 값 | 출처 |
|---|---|---|
| 입지 등급 | "1등급 · 상위 10%" (1~10) | `grid_score.grade` |
| 실측 3년 생존율 | "이 등급 자리들의 실측 74.3%" + 서울 전체 병기 | `score_meta` (하드코딩 금지) |
| 3년 기대손익 | 임대료 입력 시만 표시, 미입력 시 "임대료 입력하면 계산" | economics |
| 신뢰도 | `full` / `partial` 배지 (§4) | `grid_score` |

- 삭제: 예상 월매출(모델이 매출을 예측하지 않는다), 손익분기 단독 표기(등급 무관하게 동일해 오해 유발 — S4에서 위험반영과 쌍으로만), 적합도 92점(등급과 중복되는 유사정밀도), "매물 N건".
- 카드 타이틀: "성수2가 A블록" 같은 작명 대신 **행정동명 + 위치 앵커** ("성수동2가 · 성수역 남측 180m") — 행정동명은 B가 `grid_sgis` 조인으로 제공, 앵커는 최근접 역·거리(`grid_access`). "블록" 단어는 해상도 과장이라 전면 금지.
- 근거 줄 → 실데이터 칩 4개: `영업 점포 n` · `최근 3년 개업 ±n` · `이웃 생존율 n% (표본 m)` · `역까지 nm`. SNS·팝업·유동 배수 문구 전부 삭제.
- 상태 필: `검증된 자리`(영업 점포 상위 + 최근 급증 아님) / `과열 신호`(직전 3년 개업 급증) / 없음. "상승 초입"은 금지 — 상승을 예측한 적 없다. 필 임계값은 레인 A와 합의해 `score_meta`에 싣는다(프론트 임의 계산 금지).
- What-if 패널: `월 임대료 ±` · `범위 확대` · `업종 변경`(사전계산 12업태 즉시 전환). `공격형 전환` 삭제 — 대응되는 모델 축이 없다. **재계산은 전부 API 호출(디바운스)** — economics 산식을 클라이언트에 복제하지 않는다. 로직이 두 벌이면 반드시 어긋나고, 목업 금지 정책의 취지(화면 수치는 단일 출처)와 충돌한다.
- 정렬: 기본 등급순, 임대료 입력 시 기대손익순 토글.

**지도 패널**:
- 탭 교체: `적합도/SNS 모멘텀/임대료 부담/경쟁 밀도` → **`입지 등급` / `경쟁(점포 수)` / `지역 생존율` / `수요(행정동)`**. 수요 탭은 **같은 동 격자를 동일 색으로 채워** 사실상 동 단위로 보이게 하고(경계 shapefile 미확보로 진짜 코로플레스는 불가 — §1), 헤더에 "행정동 단위 — 같은 동은 같은 값" 캡션 고정(비협상 항목 4의 시각적 이행).
- 히트맵: 브랜드 옐로우 알파 연속 → **등급 10단 이산 램프, 단 브랜드 옐로우가 아닌 전용 순차 스케일**(§0 원칙 5와의 충돌 방지 — 전면 옐로우 히트맵은 CTA·1등급 신호를 죽인다). 램프는 **KB 블루** 10단 — KB부동산 지도가 데이터에 옐로우를 쓰지 않는 것과 같은 이유다. 범례는 10단 중 5개 대표 구간만 라벨(10단 전부 라벨은 판독 불가). 연속 알파는 "점수"라는 유사정밀도를 만든다 — 우리가 보증하는 건 십분위뿐.
- **옐로우 테두리는 "추천 목록에 오른 후보 셀"에만** (2026-07-27 구현 중 수정). 당초 "1등급 셀 전부"였으나, 한식 기준 명동·충무로 일대는 1등급이 밀집해 화면이 옐로우 격자판이 되고 강조가 무의미해졌다 — §0 원칙 5(화면당 옐로우 1곳)가 상위 규칙이므로 그 예시였던 "1등급 테두리"를 조정한다. 1등급 구분은 램프의 최짙은 색이 이미 담당하며, 후보 테두리는 목록↔지도 연결(§0 원칙 4)도 함께 강화한다.
- **매출 NULL 격자(49.5%)**: 등급 탭에서는 정상 렌더(등급은 전 격자 존재), 매출 관련 뷰에서는 **무채색 + 빗금 패턴 + 범례 "매출 정보 없음(상권 밖)"**. 0으로 그리는 순간 최악 입지로 읽힌다 — 비협상 항목 3.
- 인사이트 스트립 3칸: `진입 적기/과열/데이터 부족` → `검증된 상권` / `과열 신호(최근 급증)` / `상권 밖(부분 데이터)`.

### S4 상세 리포트 (A·B 모드 공용)

구조 유지, 서열 재편 — **경제성(6-C)이 이 화면의 주인공**이다. 단순 회수 vs 위험반영 회수의 대비는 우리만 보여줄 수 있는 화면이고 심사 서사("입지 위험의 가격")와 일치한다.

| 시안 블록 | 결정 |
|---|---|
| Hero "92점 · 상위 0.4%" | → **등급 대형 표기**: "1등급 — 상위 10% 자리" + "이 등급 자리들의 실측 3년 생존율 nn% · 서울 전체 nn%" (A1 CI 확정 시 괄호 병기). 점수·백분위 유사정밀도 금지 |
| KPI 3장 (월매출·손익분기·생존확률 62%) | → ① 등급+실측 생존율 ② 경쟁·이력 스냅샷(점포 n·개업 ±n·이웃 생존율) ③ 접근성(역·거리). 확률 % 단독 노출 금지 — 비협상 항목 5 |
| 신규 · 경제성 카드 (주인공, KPI 바로 아래 전폭) | 입력(임대료·초기투자·매출·마진 — S2 값 프리필, 인라인 수정 가능) → 출력 3열: **단순 회수 n개월 / 위험반영 회수 n개월 / 3년 기대손익 ±n만**. 매출 미입력 시 캡션 필수: "서울 상권 평균 매출 기준 — 이 격자의 추정치가 아닙니다". 하단에 등급 상/중/하 동일조건 비교 미니표("같은 조건, 자리만 다를 때"). 마진 민감도(A2): 부호가 바뀌는 구간이면 "결과가 마진 가정에 민감" 배지 + ±범위 표기 |
| "왜 이 자리인가" SHAP 금액 바 | → **정성 기여 바**: 실피처 5개(자리 교체율·영업 점포 수·최근 3년 개업·과거 생존율·역 접근성), 방향(↑생존/↓생존)과 상대 크기만, **금액·% 라벨 없음**. 캡션 "모델 가중치 기반 — 상관이며 인과가 아닙니다" |
| AI 근거 리포트 | **문단 벽 해체**(§0 슬롭 표): 3문단 박스 → "한 문장 + 숫자 칩" 목록 3~5행(LLM은 문장 생성만, 입력은 실피처·실측치로 제한, LLM 생성 태그 유지). 마지막 행은 **한계 고정 문장**(자동 삽입): "이 등급 자리에서도 약 4곳 중 1곳은 3년 내 폐업했습니다. 등급은 입지의 확률이지 성패의 보증이 아닙니다". **구현: 레인 B `/report`**(`docs/submission.md` §3) — 응답에 등장하는 숫자는 요청 payload 값의 템플릿 치환만 허용(**숫자 화이트리스트 검증** — 생성문이 payload에 없는 수치를 내면 폐기), 실패는 에러 상태로 노출(목업·폴백 금지 동일 적용) |
| 잠식 vs 집적 카드 | → **"이미 많은 곳 vs 최근 급증한 곳"** 카드: 이 격자의 영업 점포 수와 직전 3년 개업 추이를 대비시키고 검증/과열 판정 표시. −8%/+21% 같은 미검증 효과치 삭제 |
| 위험 요인 카드 | 유지하되 실데이터로: 과열 신호 여부 · partial 신뢰도 여부 · 행정동 단위 값 목록("아래 값은 동 단위 — 옆 격자와 같은 값") · 임대료 미입력 시 경고 |
| 예시 매물 3건 테이블 | **삭제.** 매물·권리금 데이터가 없다(줄 수 없는 것 목록). 대신 **면적 참고 카드**: 면적 5구간 실측 생존율 표(`score_meta` 추가분) + "순위에는 반영하지 않았습니다 — 자리가 아니라 선택의 문제라서". **층은 다루지 않는다** — 인허가 원천에 층 필드가 없어 산출 불가(README의 층 수치는 별도 소스, 제출 후 과제). S4 인라인 면적 입력 시 해당 행 하이라이트 |
| KB 대출 사이드바 | **수치 시뮬레이션 전면 제거** — 한도·금리·월 상환액은 우리에게 산식이 없어 어떤 값을 그려도 목업 금지 위반이다. "KB 창업자금 대출 상담 연결" CTA + "연계 기획" 라벨의 콘셉트 카드로 축소(연계 서사는 유지) |
| 알림 카드 | **콘셉트 카드로 축소**("연계 기획" 라벨, 구독 동작 없음) — `grid_score`는 단일 `as_of` 정적 사전계산이라 변동을 감지할 백엔드가 없다. 동작하는 척하는 구독 UI는 목업 금지 위반(대출 카드와 동일 처분) |
| 데이터·한계 사이드카드 | 전면 교체: 실출처 목록 + **AUC 0.59 = "무작위보다 나은 수준"** 명문 + 비정형 2회 측정·기여 없음 + 데이터 없는 축(임대료는 입력값·매물 정보 없음) |

## 4. 공통 컴포넌트 규칙

- **등급 배지**: `n등급` 고정 포맷 + 병기 숫자는 그 등급의 실측 생존율("1등급 · 실측 75%"). ~~"상위 nn%"~~는 2026-07-27 금지로 전환 — 등급 경계는 홀드아웃 십분위의 절대 경계라 현재 격자의 백분위가 아니다(`docs/serving-design.md` §3). 문자 등급(A+)·점수(92점) 금지 유지.
- **신뢰도 배지**: `full` = 무표기(기본), `partial` = 회색 배지 "상권 밖 — 매출·유동 정보 없음". 배지 클릭 시 어떤 축이 비는지 목록.
- **단위 캡션**: 행정동·상권 해상도 값은 값 옆에 항상 `행정동 단위`/`상권 단위` 초소형 캡션. 컴포넌트에 내장해 누락이 불가능하게 한다.
- **수치 단일 출처**: 화면의 생존율·격자 수·등급 경계는 전부 API(`score_meta`)에서. 프론트 하드코딩 금지 — 모델 재계산(실험 라운드 2) 시 화면이 자동 추종해야 한다.
- **NULL 렌더 공통 규칙 (필드 불문)**: 매출(49.5%)만이 아니라 지역 생존율(표본 부족 NULL)·수요(행정동 미매칭)도 동일 — 무채색 + 빗금 + 범례 "정보 없음". `?? 0` 대체·빈칸 방치 금지. 이것이 비협상 항목 3의 일반형이다.
- **경제성 컴포넌트 캡션 내장**: 매출 미입력 시 "서울 상권 평균 매출 기준 — 이 격자의 추정치가 아닙니다" 캡션은 경제성 컴포넌트 자체에 내장한다(S3 카드·S4 카드 공통 — 누락이 불가능하게).
- **고정 한계 스트립**: S2·S3 하단 1줄 고정 — "등급은 과거 데이터 백테스트 기반이며 무작위보다 나은 수준(AUC 0.59)입니다 · 상위 10% 자리도 약 26%는 3년 내 폐업했습니다." 문구는 API `meta()`의 한계 문구에서 온다(S1은 정직성 스트립, S4는 데이터·한계 카드가 담당 — 이로써 4개 화면 전부 커버).
- **금지어**: "생존확률 nn%"(모델 확률), "블록", "상승 초입", "적합도 점수", "예상 월매출"(모델 산출인 것처럼 쓰는 경우), **"상위 n%"(등급의 백분위 번역 — serving-design §3)**.

## 7. 실행 부록 — 컨텍스트 없는 실행자를 위한 계약

**엔드포인트 (B 초안 `service/api.py` 함수 → HTTP 매핑; 응답 필드명은 B가 확정해 `lanes/B-backend.md`에 기록하고, C는 그 기록만 참조)**

| HTTP | 원천 함수 | 용도 |
|---|---|---|
| `GET /meta` | `meta()` | 업태·자치구 목록, 등급별 실측 생존율(+CI), 한계 문구, `as_of` |
| `GET /grids?uptae&bbox` | 신설 | 뷰포트 격자 폴리곤(위경도)+등급 — 셀 수 상한 |
| `GET /recommend?uptae&districts&top` | `recommend()` | 랭킹 목록 |
| `GET /grid/{id}?uptae` | `grid_detail()` | S4 상세 |
| `GET /at?lon&lat&uptae` | `at_point()` | 진단 모드 |
| `POST /economics` | `model.economics` | 손익 3열 재계산 (What-if 포함) |
| `POST /report` | 신설 (LLM) | 근거 문장 — 숫자 화이트리스트 검증 |

**표기 규칙**
- 등급: `grade n` → "n등급" + 실측 생존율 병기 (grade 1 = 최상 — B 응답 스키마에 방향 명시). "상위 n×10%" 번역은 금지(§4).
- 업태 칩 라벨: `meta()`가 주는 값 **그대로**. "외국음식전문점"을 "외국음식"으로 줄이는 식의 가공 금지 — DB 키와 어긋나면 조회가 조용히 깨진다.
- 상태 카피(전 화면 공통): 로딩 "불러오는 중…" · 에러 "데이터를 불러오지 못했습니다 — 다시 시도" (재시도 버튼 필수) · 빈 결과 "조건에 맞는 격자가 없습니다. 범위를 넓혀보세요."

## 8. 수치 불일치 — 해소됨 (2026-07-27)

폐업률 혼선(23%/27%/37.7%)은 세 수치 계보가 섞인 것이었고 `docs/model-findings.md` §4-C로 정리됐다. 인용 기준은 순수 입지(LOC3): **상위 10% 74.3% / 하위 10% 44.8% / 폐업 약 26%**. 단 배포 `score_meta`는 아직 구세대 세트(73.1~44.1)라 재계산 대기 중(`experiment-plan.md` E0) — **UI는 계속 `score_meta` 파생만 쓰면** 재계산 시 자동으로 맞는다.
