# 디자인 자산 — KB 터(TEO) UI

`figma-snapshot/`은 Figma 파일에서 REST API로 추출한 **2026-07-26 시점 스냅샷**이고, `tokens/`는 거기서 뽑아 큐레이션한 **디자인 토큰**이다. 스냅샷은 Figma가 바뀔 때마다 통째로 갈아끼우는 생성물이고, 토큰은 손으로 관리하며 스냅샷을 갈아끼워도 이어진다 — 그래서 폴더를 나눴다.

플로우는 아직 확장 중이고, 최종 설계는 이 스냅샷을 출발점으로 별도 진행한다.

## 파일

```
figma-snapshot/
  design.json    Figma 노드 트리 원본 (GET /v1/files/:key 응답 전체)
  spec.md        화면별 계층·텍스트·색·타이포·오토레이아웃 (design.json에서 생성)
  renders/       화면별 PNG (1440px 기준)
  pull.ps1       Figma에서 다시 받아오기 (json + png + spec.md 갱신)
  extract.ps1    design.json → spec.md

tokens/
  tokens.json    큐레이션한 디자인 토큰 — 값은 실측, 이름은 사람이 붙임
  tokens.css     tokens.json에서 생성한 CSS 커스텀 프로퍼티 (생성물)
  build-css.ps1  tokens.json → tokens.css
```

## 갱신

플로우/디자인이 바뀌면:

```powershell
powershell -File figma-snapshot\pull.ps1   # design.json, renders/, spec.md 갱신
# spec.md 맨 아래 팔레트·타입 스케일 섹션을 보고 tokens/tokens.json 손본 뒤
powershell -File tokens\build-css.ps1      # tokens.css 재생성
```

Figma PAT은 `%USERPROFILE%\.figma\token.md`에서 읽는다(스코프 `file_content:read`). **토큰은 절대 커밋하지 않는다.** 화면이 추가되면 `pull.ps1`의 `$frames` 맵에 노드 ID를 추가해야 렌더된다.

`tokens.css`는 생성물이라 직접 고치면 다음 빌드에 덮인다. `tokens.json`만 고친다.

## 실측에서 드러난 정리 대상

토큰화하면서 발견한 것들. 다음 설계 라운드에서 정할 것:

1. **뉴트럴이 두 줄로 병존한다.** 쿨그레이(`#8A8A8A` 계열, 라이트 배경용)와 웜그레이(`#8A837A` 계열, 다크 배경용). 의도한 이원화면 그대로 두고, 아니면 한 줄로 합친다.
2. **1값 드리프트.** `#6A6A6A`와 `#6B6B6B`가 공존한다. 같은 역할이면 하나로.
3. **타입 스케일 20단계.** 10~56px 사이에 18개 사이즈가 쓰였다. 본문은 `11/12/13/14` 4단으로 충분해 보이고, 나머지는 통합 여지가 있다.
4. **간격이 2px 그리드다.** `tokens.json`의 `space`는 4px 그리드로 정규화했지만 원본에는 `5·6·9·10·14·18·22·26·30`이 섞여 있다. 재현이 목적이면 `spec.md`의 실값을 쓰고, 새로 그릴 거면 4px로 맞춘다.
5. **radius 14종.** `2·3·5·6·7·8·9·10·11·12·14·16·18·100`. 토큰은 사용 빈도 상위 7개만 남겼다.
6. **히트맵 셀은 브랜드 옐로우 알파 연속값**(0.15~0.93)이다. 토큰의 `heatmap.1~5`는 범례 5칸에 맞춘 대표값이고, 실제 셀은 그 사이를 연속으로 채운다.

## 시안 수치와 실측의 충돌 — 설계 전 확인 필요

시안에 들어간 숫자는 목업 값이라 실제 파이프라인·모델 결과와 어긋난다. `lanes/C-frontend.md`의 "화면에 반드시 들어가야 하는 것"(협상 대상 아님)과 직접 충돌하는 지점만 적는다.

| 시안 (화면) | 실측 (`CLAUDE.md` / `lanes/C-frontend.md`) |
|---|---|
| **SNS 언급량 증가율이 SHAP 기여 1위** (S4, +312만) · 기능 카드 1번 "SNS 반응을 매출 선행지표로" (S1) | 비정형(검색 트렌드·점포 언급량)은 **두 방식 모두 측정했고 기여가 없었다** |
| "3년 생존확률 **62%**" 같은 모델 확률 직접 노출 (S3 카드 3종, S4 KPI) | **확률 대신 등급 + 실측 생존율.** 모델 확률은 낙관 편향이라 쓰지 않는다 |
| "동일 업종 서울 평균 **41%** 대비 +21%p" (S4) | 전체 3년 생존율 **61.7%**, 등급별 실측 44.1~73.1% |
| "서울 전체 블록 **12,480개**" (S2 요약 패널) | 격자 **20,148개** (100m), `grid_score` 241,776행 |
| 모델 한계 문구가 "상관관계이며 인과 아님" 수준 (S4 사이드바) | **AUC 0.59는 "무작위보다 나은 수준"**, 상위 10%에서도 **27%는 3년 내 폐업**을 화면에 넣어야 함 |
| "블록" 단위 + 매물 3건 테이블 (S4) | 실제 해상도는 100m 격자. 행정동/상권 단위 값은 **그 단위를 표기**해야 하고 같은 동 격자는 동점 |

S1·S3·S4에 면책 문구와 "데이터 부족" 구간 표기가 이미 들어가 있는 건 방향이 맞다. 위 표는 **숫자를 실측으로 갈아끼우고 확률 표기를 등급으로 바꾸는 작업**이 남았다는 뜻이다.
