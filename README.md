# KB Previl

서울에서 음식점 자리를 고를 때, **100m 격자 단위로 "이 자리에서 실제로 몇 집이 버텼는지"** 를 보여주는 서비스입니다. 제8회 KB 미래금융 AI Challenge 출품작.

```
verify 7/8 · consistency 17/17 · 누수 가드 PASS · as-of 셀프테스트 PASS
서빙 계약 121 PASS · 제출물 3종 (코드 20.9MB · DB 69.1MB · .env) · 리허설 통과
```

`verify` 의 `counts` 는 라이브 API 총건수와 대조하는 검사라, 캐시로 재구축한 DB
에서는 원천이 갱신된 만큼 어긋납니다. 수집을 포함한 콜드런에서는 8/8 입니다.

<br>

## 무엇을 하는가

예비 창업자가 자리를 고를 때 물어볼 곳은 사실상 중개인뿐이고, 공개된 통계는
행정동에서 멈춥니다. 골목 하나 건너 갈리는 것이 장사인데 자료의 해상도가 그것을
못 따라갑니다.

이 서비스는 서울 일반음식점 인허가 **53.5만 건**(1980년대 이후 개·폐업 전체 이력)
을 100m 격자에 올리고, **개업 시점의 상권 상태를 그 시점 기록만으로 복원해서**
3년 생존 여부를 학습합니다. 학습 2005~2022 / 검증 2023 으로 시간을 분리했고,
결과는 확률이 아니라 **등급 + 그 등급 자리들이 실제로 버틴 비율**로 냅니다.

| 화면 | 답하는 질문 |
|---|---|
| 랜딩 | 좋은 자리인지 어떻게 아나 |
| 조건 입력 | 업종·범위·예산을 넣으면 후보가 몇 곳인가 |
| 결과 지도 | 서울 어디에 그 자리들이 있나 |
| 상세 리포트 | 이 자리는 어떤 자리이고, 이 조건이면 3년 뒤 얼마가 남나 |
| 매물 비교 | 이미 본 매물 2~3곳 중 실제로 싼 곳은 어디인가 |

## 빠른 시작

제출물을 받은 경우, `previl/` 폴더에서 명령 하나면 됩니다. `pip install` 도
`npm install` 도 API 키도 직접 할 필요가 없습니다.

```bash
python run.py
# http://127.0.0.1:8000 이 저절로 열립니다
```

`run.py` 가 전용 가상환경을 만들고 의존성을 설치한 뒤, DB 가 있으면 바로 띄우고
**없으면 `.env` 를 읽어 백필을 시작**합니다. FastAPI 가 `web/`(빌드된 화면)을
같은 origin 에서 서빙하고, 데이터는 동봉된 경량 DB(`kb-demo.db`, 255MB)에서
읽습니다. 인터넷 없이 동작합니다(지도 배경 타일만 예외).

저장소에서 바로 띄울 때도 같습니다 — `run.py` 가 `kb.db` 를 먼저 찾습니다.

개발할 때는 프런트를 따로 띄웁니다.

```bash
python -m uvicorn service.app:app --reload --port 8000
cd frontend/app && npm install && npm run dev   # http://localhost:5173
```

## 핵심 수치

| | |
|---|---|
| 인허가 이력 | 535,715건 (좌표 보유 89.1%) |
| 100m 격자 | 23,573개 (데이터가 닿는 셀) |
| 채점된 격자 | 20,148개 × 12업종 = `grid_score` 241,776행 |
| 상권 내 격자 | 11,901개 (50.5%). 나머지는 매출이 NULL |
| 모델 | LightGBM · AUC **0.6383** (seed=0 단일 적합 = 배포되는 그 적합) |
| 베이스라인 | 최고 `prior_surv` 0.5668 → **마진 +0.0714** |
| 1등급 자리 | 실측 3년 생존율 **80.1%** (95% CI 75.4~84.2 · n=317) |
| 9등급 자리 | 실측 3년 생존율 **10.1%** (95% CI 7.2~13.9 · n=317) |
| 서울 전체 | 58.6%. 2013년 개업 71.3% → 2022년 개업 58.6% 로 계속 내려가는 중 |

**AUC 는 반드시 베이스라인과 함께 읽어야 합니다.** 0.6383 단독은 "무작위보다 조금
나음"으로 읽히지만, 실제 주장은 "그 자리의 과거 기록을 그대로 보는 것보다
+0.0714 낫다" 입니다.

**입지 위험에는 가격이 붙습니다.** 매출·비용이 완전히 같아도 1등급 자리는 3년
기대손익 +360만원, 9등급은 −5,638만원입니다. 차이 5,998만원이 순수하게 등급별
실측 생존곡선에서 나옵니다. 단 이 값은 마진 가정에 민감해서, 마진 20%면 세 등급
모두 적자입니다.

**작은 가게일수록 자리가 중요합니다.** 25㎡ 미만은 1·9등급 격차가 34.9%p 인데
90㎡ 이상은 15.0%p 입니다. 자본이 적을수록 이 서비스가 더 필요합니다. 이 두 값만은
legacy 벤치(학습 2005~2018 / 검증 2019~2022)에서 잰 것이라 위 표의 배포 계보
숫자와 이어 붙이면 안 됩니다.

## 구조

```
데이터        pipeline/    수집 → 정규화 → 격자 매핑 → 피처
모델          model/       as-of 복원 → 학습 → 백테스트 → 채점
서빙          service/     FastAPI + SQLite (읽기 전용), API 14경로
화면          frontend/    React + TypeScript + MapLibre
근거          probe/       실측 스크립트 (수정 금지)
```

세 레인이 병렬로 작업하며 `model/`=A, `service/`=B, `frontend/`=C 가 소유합니다.
`pipeline/` 은 공유이고 `kb.db` 쓰기는 A 만 합니다. 규칙은 `lanes/README.md`.

| 모듈 | 역할 |
|---|---|
| `pipeline/config.py` | 좌표계·업종코드·기준선 단일 출처 |
| `pipeline/grid.py` | 100m 격자(EPSG:5179)와 좌표계 변환 |
| `pipeline/collect·normalize·geocode·features` | 수집에서 격자 피처까지 |
| `pipeline/verify·consistency` | 적재 검증 / 논리 정합성 게이트 |
| `model/asof.py` | **as-of 피처 복원. 누수 차단의 핵심** |
| `model/dataset·evaluate·train` | 라벨 · 평가 하니스 · 후보 6종 |
| `model/cache.py` | 스플릿 디스크 캐시 (피처 코드 해시로 자동 무효화) |
| `model/backtest·robustness·stratified` | 실효성 검증 |
| `service/api.py` | 조회 계층. 점수는 감추고 등급과 실측치만 낸다 |
| `service/economics·goodwill·estimation` | 손익 시나리오 · 권리금 참고가 · 실질 점유비용 |
| `service/demo_db.py` | 제출용 경량 DB 추출 (테이블 목록을 코드에서 재도출) |

## 전체 재현

저장소는 **코드만** 담습니다. `kb.db`·`pipeline/cache/`·학습된 모델 아티팩트는
전부 gitignore 이고, `service.precompute` 가 순위 모델을 매번 학습합니다. clone
한 사람은 아래로 전부 만들어야 합니다.

```bash
cp .env.example .env                      # 키 4종을 채운다
python -m pipeline.bootstrap --preflight   # 키·경로·잔여 쿼터 점검 (네트워크 호출 없음)
python -m pipeline.bootstrap --gates       # 수집 → … → grid_score → 게이트
```

18단계입니다: `schema → collect → normalize → tier2 → cohort → grid → geocode →
sgis → sgis_match → features → access → addr_history → concept → concept_mix →
precompute → ui_curves → succession → party`.

`tier2`(휴게음식점)는 `concept_mix` 보다 앞이어야 합니다. 카페·베이커리는 일반
음식점이 아니라 휴게음식점으로 인허가되고 `concept_mix` 가 그 표를 읽습니다.

> `pipeline.run` 은 이 일을 못 합니다. features 까지만 돌고 `grid_score` 를 만들지
> 않아 추천이 빈 목록이 되며, 센서스 단계가 없어 `corp_cnt` 가 전부 NULL 로 남습니다.

않고 `/api/report` 하나만 씁니다.

조회도 각각 별도 쿼터입니다.

## 검증

```bash
python -m pipeline.verify        # 적재 8종
python -m pipeline.consistency   # 논리 정합성 17종
python -m model.test_leakage     # 누수 가드 RED→GREEN
python -m model.asof --selftest-cut     # 신규 피처: T 이후 행을 지워도 값 불변
python -m pytest service/               # 서빙 121종
```

깊이 들어가려면:

```bash
python -m model.backtest --model gbm --features DEPLOY    # 9등급 실측 생존율
python -m model.robustness --model gbm --features DEPLOY  # 상식 규칙·연도·업태·지역
python -m model.stratified        # 면적 통제 후 입지 효과
python -m model.tournament --criterion decile   # 모델 토너먼트
python -m model.ablation_run      # 피처군 절제표
```

`consistency` 의 `district`·`dongaccuracy` 는 역지오코딩으로 좌표계를 외부
검증하므로 `KAKAO_REST_API_KEY` 와 네트워크가 필요합니다. 없으면 실패가 아니라
건너뜁니다.

### 제출물 만들기

산출물은 **3종**입니다 — 코드 zip(`previl/` 하나로 풀림) · DB zip · `.env`.
서비스가 바뀌면 이 명령 하나만 다시 돌리면 됩니다.

```bash
python -m service.demo_db --out kb-demo.db   # 서빙 의존 16개 테이블만 추출
python build.py --rehearse                   # 게이트 → 프론트 확인 → 3종 빌드 → 리허설
```

`build.py` 는 네 단계입니다.

1. **게이트** (`tools/audit.py`) — 진입점에서 도달하지 않는 모듈이 섞이지 않았는지,
   출하 소스에서 주석·독스트링이 남김없이 걷혔는지, 사유 없이 400줄을 넘는 파일이
   없는지, 그리고 **벗겨낸 트리에서 서빙 계약 121종이 그대로 통과하는지**.
2. **프론트 확인** — `src` 가 `dist` 보다 새로우면 다시 빌드합니다. 낡은 화면이
   나가는 것을 막습니다.
3. **빌드** (`tools/package.py`) — `SUBMISSION/` 에 3종을 만듭니다. 포함 목록은
   allowlist 입니다. denylist 는 패턴 하나를 빠뜨리면 `.env` 가 나가지만,
   allowlist 는 빠뜨리면 빌드가 실패합니다. 둘 중 복구 가능한 실패만 택했습니다.
4. **리허설** — 빈 임시 폴더에 코드 zip 과 DB zip 을 풀고, **새 가상환경을 만들어
   `run.py` 로 실제 기동**합니다. 작업 트리에만 있고 zip 에는 없는 파일이 실행을
   구제하지 못하게 하려는 것입니다.

출하 소스의 주석은 `tools/strip.py` 가 **빌드 시점에** 걷어냅니다. 저장소 소스는
그대로입니다 — 이유는 `docs/decisions/2026-08-01-strip-comments-at-packaging.md`.

## 설계 원칙 다섯 가지

전부 실제로 사고가 났던 지점입니다.

**1. 좌표계는 문서가 아니라 실측으로 정한다.** 인허가는 EPSG:5174, 서울 상권은
EPSG:5181 로 서로 다릅니다. 후보 좌표계들은 원점을 공유하고 datum 만 달라서, 틀린
것을 골라도 점이 서울 안에 그럴듯하게 떨어집니다. 실제로 처음 EPSG:2097 로
가정했고 **내부 검증 14/14 가 통과하는 상태에서 전 점포가 1~2 격자 밀려**
있었습니다. 역지오코딩으로 각 레코드의 주소와 대조해서야 잡혔습니다. 바꾸려면
`probe/p8_crs.py` 부터.

**2. 데이터가 없으면 NULL 이지 0 이 아니다.** 상권 밖 격자(49.5%)에 매출 0 을
넣으면 그 자리가 "최악의 입지"로 랭크돼 추천이 조용히 거짓이 됩니다.
`verify nullzero` 와 `consistency nullnotzero` 가 이것을 지킵니다.

**3. 거친 데이터를 격자로 배분하지 않는다.** 행정동 인구를 격자에 나눠 담으면
산과 하천에도 인구가 배정됩니다. 거친 값은 "이 격자가 속한 단위의 값"으로 표기해
붙이고, 같은 행정동 격자들은 그 피처에서 동점이 됩니다. **격자 간 순위는 점 단위
피처만이 결정합니다.**

**4. 생존율의 분모는 관측 가능한 부분이다.** `1 − (N년 내 폐업) / (개업 후 N년이
이미 지난 점포)`. 2025-11 개업 점포는 3년 테스트를 못 치렀으므로 분자·분모 어디에도
안 들어갑니다. "폐업한 가게 중 N년 못 버틴 비율"과 혼동하면 안 됩니다. 그것은
실패에 조건부라 예측에 못 씁니다.

**5. 점포 속성과 입지를 섞지 않는다.** 면적은 단일 최강 예측자입니다(면적만으로
AUC 0.6227). 하지만 점포 속성이지 입지가 아니고, 추천에서는 사용자가 정하므로 모든
후보에 같은 값이 들어갑니다. 순위·보정 모두 면적을 뺀 모델을 씁니다. 층도
마찬가지인데, **층별 생존율은 아예 인용하지 않습니다.** 종전 수치는 개·폐업일이
없는 테이블을 출처로 달고 있어 산출 자체가 불가능했고, 유일하게 가능한 원천으로
재보면 지하가 8.6배 과대표집된 데다 면적으로 층화하는 순간 층 차이가 사라집니다.
층으로 보이던 것은 면적이었습니다(`docs/tracking/findings.md` F-A5).

<br>

## 정직하게 남겨둔 것

이 프로젝트에서 기각은 실패가 아니라 결과입니다. 전체 대장은
`docs/model-findings.md` §0 에 51건이 판정과 근거 수치와 함께 있습니다.

**비정형으로 예측하려는 시도는 아홉 번 전부 기각됐습니다.** 예측 정확도 3회,
지명 단위로 용도를 바꿔 3회, 실거래가 1회, LLM 으로 뽑은 방문 시간대 1회, 1인당
지출 1회. 검정력도 확인했습니다(트렌드 재검정 최소검출효과 +0.0027 < 임계
+0.005). 못 본 것이 아니라 없었습니다.

**왜 안 되는지도 쟀습니다.** 검색 관심도와 실제 유동인구의 상관이 ρ=+0.079
(CI −0.071~+0.218)입니다. 트렌드가 예측을 못 하는 것이 아니라, 재고 있는 것이
상권의 실제 활동량과 연결되어 있지 않습니다.

**도구가 고장난 것은 아닙니다.** 인허가 업태를 정답으로 놓고 "블로그 글만 보고
업종 맞히기"를 채점했더니 macro-F1 0.4701(무작위 0.143 · 점포 3,176곳)이었습니다.

**재현성 통과와 정확도 통과는 다릅니다.** 경쟁자 약점 추출은 2차 판정 일치율
99.6% 로 통과했었지만, 그 0.996 은 2,100셀에서 positive 기대값이 13.3셀이라
"둘 다 false"가 만든 값이었습니다. 라벨이 붙은 글만 골라 다시 판정하니 정밀도
8.7~16.7% 로 7범주 전부 기준 미달이었고, 구제 시도 셋도 전부 기각됐습니다.
`text_profile` 은 화면에 내보내지 않습니다.

| 기각된 것 | 결과 |
|---|---|
| 인허가 파생 피처 15개 | ΔAUC 0.0000. 이 원천은 포화 |
| 휴게음식점 5개 | ΔAUC +0.0006, CI 가 0 을 포함 |
| 지하철 승하차·접근성 6개 | 홀드아웃 기여 판별 불가 |
| 검색 트렌드 2개 | 절제표에서는 기여로 보였으나 **위약 대조**에서 위양성 |
| 모델 교체 (후보 6종) | 제품이 쓰는 기준에서 현행 LightGBM 보다 나은 것 없음 |
| 앙상블 (무가중 결합 5종) | 배포 계보에서 +0.13%p [−2.53, +1.90]. 재측정 결과 **등록 임계 자체가 검출 불가**였다 (MDE +2.81%p vs 임계 +0.5%p) |
| 동급 상권 군집화(E6) | 업종 내 점포당 매출 분산의 13%만 설명 (요구 20%) |

**함께 말해야 할 한계**

- 1등급 자리에서도 약 20% 는 3년 내 폐업하고, 9등급에서도 10.1% 는 살아남습니다.
  입지는 일부일 뿐입니다.
- AUC 0.64 는 "무작위보다 나은 수준"이지 "잘 맞힌다"가 아닙니다.
- 코로나가 입지의 측정 가능한 가치를 눌렀습니다. 2019~2022 검증에서 십분위 격차가
  30.6%p 인데 2023 코호트에서는 47.7%p 입니다. 그 차이는 코로나 탈출과 학습창
  확대가 거의 반씩(52% / 48%) 만들었습니다.
- 양끝 등급 격차 70.0%p 는 구간 모양의 부산물이지 모델 성능 개선이 아닙니다.
  게다가 시드에 민감합니다 — 시드 8개로 재보면 67.5~70.0%p 이고 배포분이 그중
  최대값입니다. 1등급 80.1% 는 반대로 강건해서 8개 시드가 전부 발표 CI 안에
  듭니다.
- 미확보 원천: 공정위 창업비용, R-ONE 임대료, VWORLD 물리입지, 집계구 경계.
