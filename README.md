# 서울 요식업 입점 위치 추천

공모전 출품작의 기술 파트. 서울 어느 지점이든 **100m 격자** 단위로 경쟁·생존·수요·비용을 조회하고, **과거 데이터로 검증된** 입지 등급을 매긴다.

**상태: 데이터 파이프라인 + 생존예측 모델 + 비용 시나리오 완료.** UI 미착수.

```
verify 8/8 · consistency 17/17 · as-of selftest PASS · ≤T 셀프테스트 PASS · 누수 가드 PASS
```

`consistency`의 `district`·`dongaccuracy`는 역지오코딩으로 좌표계를 외부 검증하므로
`KAKAO_REST_API_KEY`와 네트워크가 필요하다(없으면 실패가 아니라 건너뜀).

---

## 한 문단 요약

서울 일반음식점 인허가 **53.5만 건**(1900~2026, 개·폐업 전체 이력 — 밀도는 1980년대부터)을 100m 격자에 올리고, 개업 시점의 상권 상태를 인허가 이력만으로 복원해(as-of) 3년 생존 여부를 학습했다. 학습 2005–2022 / 검증 **2023**으로 시간 분리했고, **1등급 자리의 실측 3년 생존율은 80.1%(95% CI 75.4–84.1), 전체 평균은 58.6%**다. 검증 코호트를 2023으로 옮긴 이유는 2019–2022가 여러 라운드에 걸쳐 반복 조회돼 더 이상 깨끗한 시험셋이 아니기 때문이다. 여기에 실측 생존곡선을 곱해 "이 자리에서 이 임대료면 3년 뒤 얼마가 남는가"를 계산한다.

모델은 후보 6종(로지스틱·LightGBM·RandomForest·ExtraTrees·HistGB·MLP)을 **내부 검증에서 겨뤄** 고르고 홀드아웃으로 확인했다. 결과는 **현행 LightGBM 유지** — 내부 검증 승자(RandomForest)가 홀드아웃에서 상위 10%를 −0.12%p [−0.94, +0.98] 움직여 채택 기준에 미달했다. "여러 모델을 검증했고, 제품이 쓰는 기준에서는 현행보다 나은 것이 없었다"가 정확한 문장이다(§7-A).

| 모델 (순수 입지) | LightGBM · AUC **0.6383** (seed=0 = 배포분) · 최고 베이스라인 0.5668 · **마진 +0.0715** |
| 1등급 자리 | 실측 생존율 **80.1%** (75.4–84.1) · n=317 · 전체 58.6% |
| 9등급 자리 | 실측 생존율 **10.1%** (7.2–13.9) · n=317 |
| 양끝 등급 격차 | **70.0%p** — 구간 모양의 부산물이며 모델 성능 개선이 아니다 |
| 등급 경계 | 등분위10·정규형10·내신형9를 사전 고정해 비교하고, 역전 해소와 꼬리 표본을 근거로 내신형9 채택 |

**입지 위험의 가격**: 매출·비용이 완전히 같아도 1등급 자리는 3년 기대손익 +360만, 9등급은 −5,638만이다. 차이 5,998만원이 순수하게 배치 실측 생존곡선에서 나온다. 단 이 값은 마진 가정에 민감하다 — 마진 20%면 세 등급 모두 적자이고, 30%에서도 9등급은 적자다.

**타깃이 분명하다**: 작은 가게일수록 입지가 중요하다. 25㎡ 미만은 1·9등급 격차가 **34.9%p**인데 90㎡ 이상은 15.0%p다(`score_meta.observed_by_grade_area`, legacy 벤치 — 화면이 내보내는 값). **자본이 적을수록 이 서비스가 더 필요하다.**

## 콜드 스타트 — 빈 상태에서 서비스까지

이 저장소는 **코드만** 담는다. `kb.db`·`pipeline/cache/`·`model/.cache/`는 전부
gitignore이고 **학습된 모델 아티팩트도 추적되지 않는다**. `service.precompute`가
순위 모델을 매번 학습하므로, clone한 사람은 아래 한 줄로 전부 만들어야 한다.

```bash
cp .env.example .env      # 키 4종을 채운다
python -m pipeline.bootstrap --preflight    # 키·경로·잔여 쿼터 점검 (네트워크 호출 없음)
python -m pipeline.bootstrap --gates        # 수집 → … → grid_score → 게이트
```

17단계다: `schema → collect → normalize → **tier2** → cohort → grid → geocode →
sgis → sgis_match → features → access → addr_history → concept → concept_mix →
precompute → ui_curves → succession`.

`tier2`(휴게음식점)는 `concept_mix`보다 앞이어야 한다. 카페·베이커리는 일반
음식점이 아니라 휴게음식점으로 인허가되고, `concept_mix`와 서비스의 까페 집계가
그 표를 읽는다 — 빠지면 `no such table: licence_rest`로 죽는다.

**`pipeline.run`은 이 일을 못 한다.** features까지만 돌고 `grid_score`를 만들지
않아 추천이 빈 목록이 되며, 센서스 단계가 없어 `corp_cnt`가 전부 NULL로 남는다.

### 필요한 키

| 키 | 쓰는 곳 | 없으면 |
|---|---|---|
| `SEOUL_OPEN_API_KEY` | 인허가·상권·생활인구 수집 | collect 불가 |
| `KAKAO_REST_API_KEY` | 격자 중심 → 행정동 역지오코딩 | geocode 불가 |
| `SGIS_CONSUMER_KEY` / `_SECRET` | 센서스 | 배후인구 피처 결측 |
| `DATA_GO_KR_SERVICE_KEY` | SEMAS 점포 | 완주는 하나 `consistency`의 `crosssource`가 실패 |

`OPENAI_API_KEY`는 **필요 없다.** 기각된 비정형 실험에서만 쓰였고 콜드스타트
경로에 없다.

### 시간과 쿼터

| 단계 | 캐시 있을 때 |
|---|---|
| normalize (53.5만 행) | 33초 |
| features · access · sgis | 7초 |
| addr_history | 13초 |
| concept | 78초 |
| precompute (모델 학습 + 채점) | 59초 |
| succession (M2) | 68초 |
| **ui_curves** (1·3·5년 곡선 × 등급 × 면적대) | **895초** |

캐시가 없으면 여기에 수집이 붙는다. 서울 열린데이터는 **일일 900콜**인데
실측(`collect --dry-run`, 2026-07-29) 합계가 **857콜**이다 — 인허가 536 ·
휴게음식점 147 · 점포 76 · 생활인구 72 · 추정매출 22 · 상권영역 2 · 길단위인구 2.
**여유가 43콜뿐이다.**
**중간에 끊기면 다음 날 같은 명령을 다시 치면 이어서 받는다** — 각 단계는 출력
테이블이 차 있으면 건너뛰고, 캐시가 있는 수집분은 호출을 다시 쓰지 않는다.
`--from <단계>`로 지점을 지정할 수도 있다. 어느 캐시가 있고 몇 콜이 남았는지는
`--preflight`가 낱개로 알려준다.

SEMAS(소상공인 상가업소)는 **data.go.kr 별도 쿼터**라 위 900콜과 무관하다.
KAKAO 역지오코딩(격자 23,573)과 지하철역 조회도 각각 별도 쿼터다.

**어디까지 검증됐는지**: 빈 DB → 서비스까지는 실제로 돌려 확인했다(17단계 완주 ·
게이트 3/4 · 운영 DB 와 등급·콘셉트·헤드라인 다이제스트 일치). 다만 그 실행에서
`collect`·`geocode`·`sgis` 는 **캐시가 받아냈다**. 원천에서 실제로 내려받는
경로는 `collect --dry-run` 으로 7개 엔드포인트가 응답하고 총건수가 맞는 것까지만
확인했다 — 전량 수집 완주는 하루 쿼터를 다 쓰므로 아직 돌려보지 않았다.

### 알아둘 것

`pipeline.verify`의 `counts` 검사는 **라이브 API의 총건수와 대조**한다
(`verify.py:62`). 캐시가 원천보다 오래되면 그만큼 어긋나 실패한다 — 캐시로만
재구축한 DB에서 7/8이 나오는 건 이 이유이고, 수집을 포함한 콜드런에서는 통과한다.

## 알아야 할 다섯 가지

### 1. 좌표계는 문서가 아니라 실측으로 정했다
인허가는 **EPSG:5174**, 서울 상권은 **EPSG:5181**. 서로 다르다.

후보 좌표계들은 원점을 공유하고 datum만 달라, 틀린 걸 골라도 점이 서울 안에 그럴듯하게 떨어진다. 실제로 처음 EPSG:2097로 가정했고 **내부 검증 14/14가 통과하는 상태에서 모든 점포가 1~2 격자 밀려 있었다.** 역지오코딩으로 각 레코드의 주소와 대조해서야 잡혔다. 좌표계를 바꾸려면 `probe/p8_crs.py`부터 돌릴 것.

### 2. 데이터가 없으면 NULL이지 0이 아니다
상권 밖 격자는 매출·유동인구가 NULL이다. 0을 넣으면 그 자리가 "최악의 입지"로 랭크돼 추천이 조용히 거짓이 된다. `verify nullzero`와 `consistency nullnotzero`가 이걸 지킨다.

### 3. 거친 데이터를 격자로 배분하지 않는다
행정동 인구를 격자에 나눠 담으면 산과 하천에도 인구가 배정된다. 거친 값은 **"이 격자가 속한 단위의 값"**으로 표기해 붙이고, 같은 행정동 격자들은 그 피처에서 동점이 된다. **격자 간 순위는 점 단위 피처만이 결정한다.**

### 4. 생존율의 분모는 관측 가능한 부분이다
`survive_Ny = 1 − (N년 내 폐업) / (개업 후 N년이 이미 지난 점포)`. 2025-11 개업 점포는 3년 테스트를 못 치렀으므로 분자·분모 어디에도 안 들어간다. **"폐업한 가게 중 N년 못 버틴 비율"과 혼동하지 말 것** — 그건 실패에 조건부라 예측에 못 쓴다.

### 5. 점포 속성과 입지를 섞지 않는다
면적은 단일 최강 예측자다(면적만으로 AUC 0.6221, 25㎡ 44.8% ↔ 90㎡+ 74.4%). 절제표에서도 면적군을 빼면 ΔAUC가 +0.0445로 어느 입지 피처군보다 크다(§7 G6). 하지만 **점포 속성이지 입지가 아니고**, 추천에서는 사용자가 정하므로 모든 후보에 같은 값이 들어간다. 순위·보정 모두 면적을 뺀 모델을 쓴다. 층도 마찬가지지만, **층별 생존율은 아예 인용하지 않는다.** 종전 수치(지하 59.8 / 1층 66.2 / 2층 69.9)는 개·폐업일이 없는 테이블을 출처로 달고 있어 산출 자체가 불가능했고, 유일하게 가능한 원천(인허가 주소의 층 토큰, 21.9%)으로 재보면 지하가 8.6배 과대표집된 데다 **면적으로 층화하는 순간 층 차이가 사라진다.** 층으로 보이던 것은 면적이었다 — 수치표는 `docs/tracking/findings.md` F-A5.

## 정직하게 남겨둔 것

- **비정형으로 예측하려는 시도는 아홉 번 다 실패했다.** 예측 정확도 3회(검색 트렌드 · 점포 언급량 · 트렌드 재검정), 용도를 바꿔 지명 단위로 3회(지역 생존 · 지역 성장 · 업종 구성 변화), 실거래가 1회, LLM으로 뽑은 방문 시간대 1회(§16), 1인당 지출 1회(§17). 검정력도 확인했다(트렌드 재검정 최소검출효과 +0.0027 < 임계 +0.005) — **못 본 게 아니라 없었다.**
- **왜 안 되는지도 쟀다.** 검색 관심도와 실제 유동인구의 상관이 **ρ=+0.079**(CI −0.071~+0.218)다. 트렌드가 예측을 못 하는 게 아니라, **재고 있는 것이 상권의 실제 활동량과 연결되어 있지 않다.** (§11)
- **그런데 도구가 고장난 것은 아니다.** 인허가 업태를 정답으로 놓고 "블로그 글만 보고 업종 맞히기"를 채점했더니 **macro-F1 0.4701**(무작위 0.143 · 점포 3,176곳)이었다. 비정형 실험 중 정답 라벨이 있는 첫 사례다. (§17)
- **재현성은 통과했지만 정확도가 기각됐다 — 비정형에서 제품에 남은 것은 없다.** 경쟁자 약점(대기 · 좌석 · 응대 · 위생 · 가격 · 소음 · 주차)은 2차 판정 일치율 99.6%로 통과했었다. 그런데 그 0.996은 300건×7범주=2,100셀에서 **positive 기대값이 13.3셀**이라 "둘 다 false"가 만든 값이었다. 라벨이 붙은 글만 골라 두 판정자가 1차 라벨을 보지 않고 다시 판정하니 **정밀도 8.7~16.7%**, 7범주 전부 기준 미달이다. 1차가 불만을 붙인 글의 **32~61%에서 두 판정자가 모두 "그런 불만 없다"**고 했다. **같은 라벨을 두 번 내놓는 것과 그 라벨이 맞는 것은 다르다.** (§18 · `text_profile` 비노출)
- **살려보려고 세 가지를 더 재봤고 셋 다 기각됐다.** ① 검색어를 주제별로 확장해 근거를 더 얻는다 → 밀도 0~7.5%로 0/6, 그 과정에서 **글의 36.4%는 본문에 상호명이 아예 없다**는 수집 결함까지 드러났다. ② 추출기를 gpt에서 haiku·sonnet으로 바꾼다 → 0.360 / 0.615. 이때 **sonnet이 뽑은 것을 sonnet이 다시 판정하면 0.250**이었다. ③ 라벨을 거칠게 해서 방문 목적(식사·카페·술)만 본다 → 0.533~0.600. ③은 판정자 간 **κ 0.48~0.76으로 측정이 성공한 상태의 기각**이고, 방문기 91~95% · 대상 점포 일치 81~83%라 관련성 탓도 아니다. **범주를 거칠게 해도, 추출기를 바꿔도 안 된다 — 147자 스니펫이라는 재료의 한계다.** (§19)
- **`visitorParty`는 예측 피처가 아니라 검정된 표기다.** §J-1 표기 문턱을 통과한 `family`(정밀도 0.633)와 `work`(0.700)만 화면에 정확도와 함께 내보내고, `alone`·`couple`·`friend`는 기각돼 노출하지 않는다. 방문객 관점의 상권 단위 관측이며 순위에는 쓰지 않는다. **비정형 예측 검정 누계 13건 · 채택 0 은 그대로다.** 표기 문턱의 통과이지 피처 문턱의 통과가 아니다.
- **인허가 이력 파생 피처는 포화**다. 파생 7개 추가 ΔAUC 0.0000에 이어, 다른 메커니즘(공실 회전·체인 비중·격자 나이 등 8개)을 새로 만들어도 홀드아웃 기여를 판별할 수 없었다.
- **휴게음식점(카페·패스트푸드)을 넣어도 안 올랐다.** 경쟁 피처가 일반음식점만 세고 있어 카페가 통째로 안 보인다는 지적은 옳았고 데이터도 채웠지만(14.7만 건), 번들 홀드아웃 ΔAUC는 +0.0006으로 CI가 0을 포함한다.
- **지하철 접근성의 기여는 판별 불가**다. 이전에 적었던 "+0.0025"는 신뢰구간 없는 단일 적합 차이였고, 짝지은 부트스트랩으로 다시 재니 CI가 0을 품는다(§7 G4).
- **새 원천 5종이 전부 기각됐다.** 인허가 재파생 8개 · 휴게음식점 5개 · 지하철 승하차 2개 · 지하철 접근성 4개 · 검색 트렌드 2개. 이 중 하나(트렌드)는 절제표에서 CI가 0을 벗어나 "기여"로 보였는데, **위약 대조**(같은 컬럼을 행 방향으로 섞어 30회 반복)를 붙이자 위양성으로 판명됐다.
- **1등급 자리에서도 약 20%가 3년 내 폐업**하고, 9등급에서도 10.1%가 살아남는다(9등급 n=317, 95% CI 7.2–13.9%). 입지는 일부일 뿐이다.
- **AUC 0.64는 무작위보다 나은 수준**이지 "잘 맞힌다"가 아니다.
- **코로나가 입지의 측정 가능한 가치를 눌렀다.** 같은 모델·같은 세트로 2019–2022를 검증하면 십분위 격차가 30.6%p인데, 정상화된 2023 코호트에서는 47.7%p다. 다만 그 차이는 **코로나 탈출과 학습창 확대가 거의 반씩** 만든 것이다(§9-A 2×2 분해, 2026-07-31 원천 재적재분 재계산 — 검증창 52% / 학습창 48%).
- **모델을 바꿔서 얻은 것은 없다.** 후보 6종을 AUC 기준·십분위 기준 두 번 겨뤘고, 제품이 쓰는 기준에서는 현행 LightGBM보다 나은 모델이 없었다.
- **동급 상권 군집화(E6)는 실패했다.** 구조 변수만으로 만든 군집이 업종 내 점포당 매출 분산의 13%만 설명한다(요구 20%). 권리금 리포트의 벤치마크는 서울 전체 업종 평균(Level 4)으로 강등됐다.
